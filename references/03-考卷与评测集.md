# 3 考卷与评测集

> **本章角色**：[全局地图 3](00-全局地图.md) 的展开正文。**P2 评测资产层**——"被检方提供物 = 测试集 / 自评基建 / 判分口径 / 目标值"，拿不出该层即查不动，报告记"该层未评估"。
> **一句话**：查"拿什么验、考卷本身可不可信"——判考卷层**齐不齐、会不会自己考自己、分数能不能信**；注意本章查的是**尺子**（评测资产健壮性），不是用尺子量 Agent 得分——Agent 能力得分量化供 3.7 应用与报告，好坏目标值归 5。
> **本章边界（防越界三句）**：（1） 3 查的是**尺子本身**（自评基建/套件构成/基线/污染/节奏），不替 4 判"怎么算对"、不替 5 定"多少算好"——判分器可信度归 4，目标值与门禁线归 5；（2） 评测跑出来的**安全/越权结果**不在此判合规与处置，归 7（红线与回归）与 9（证据等级），3 只保证"安全回归这层跑不跑得动"；（3） 查出"题目可能进了训练/开发数据"这类污染，按 3.5 口径定性与 9.2 证据降级处理，不凭一句"应该没问题"放行。
> **使用方式**：逐条过检查点——（1） 达标/不达标/警示 （2） 证据（eval 入口/套件目录/CI 配置/命令输出） （3） 不达标/警示 落整改建议。判点是**考卷层代码与资产判定**：问"这套卷子建没建、禁不禁得住查、有没有人养"，不臆断被测 Agent 能力。
> **依据原则**：正文判据与阈值全部自含、可直接执行，不依赖任何本地文件取信息；多源阈值并存时在文中标"参考口径"并注明可按名联网检索的一手来源，不当铁律。
> **溯源参考（联网可检索，非本地依赖）**：本章判据由多源公开资料交叉收敛——Anthropic《构建可信评估体系（Evaluating AI Agents）》（20-50 起步 / 歧义即噪音 / 对结果评分 / 饱和监控 / 评估驱动开发）；ABC Agent Benchmark Checklist（效度 / 基线三件套 / 环境冻结 / 披露义务，43 项）；棱镜空间三层评测金字塔（PR/日/周/实时节奏 / CI 门禁 pass@8≥80% / 双 k 同测）；Datawhale《动手学大模型应用开发》第十二章（BFCL/GAIA 难度递进与分难度单报）；awesome-agentic-ai-zh Stage 7（上线四步门禁 / 案例自真实失败 / 八元件）；污染检测公开文献（6-gram/Jaccard/CoDeC，Zep 自报 84%到复测 58-75% 等刷分案例）；公开事故报道（OSWorld 过时网站 46 任务 13 坏、tau-bench "什么都不做"通过 38%、SWE-Lancer 测试文件被覆盖）。以上复核按名检索即可。

## 3.1 自评基建（被评对象是否"自己会考自己"）

**查什么**：不管有没有外部卷子，Agent 自身要能"一键考自己"——eval 可运行入口、失败能阻断（挂 CI）、用例与代码分离、执行隔离。没有这条，后面所有评测都是外挂一次性动作。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.1.1 | 可运行的 eval 入口 | 一条命令跑全量评估（如 `agentbase eval`），支持用例/套件筛选 | 评估代码存在但零接线，只能 docstring 引用、手跑 |
| 3.1.2 | 独立失败门禁 | 评估失败返回非零退出码，**可挂 CI 当回归门禁**，坏即阻断；Eval 证据不过不进部署 | 结果只打印，坏不阻断合并/发布 |
| 3.1.3 | 用例声明化管理 | 用例以 YAML/JSON 等声明式定义，与代码分离、可版本管理（rubric 判据同样声明化，不靠人肉口述） | 用例硬编码在代码里，无法独立维护 |
| 3.1.4 | 隔离执行 | 每用例独立环境/上下文，无共享状态 | 用例间共享状态导致假失败/假成功 |
| 3.1.5 | 评估驱动开发（eval-first） | 新能力先建 eval 再实现（先有尺子后干活）；失败用例先于修复 | 功能做完才补评估，评估只是事后展示 |

**检测注意事项（3.1）**：
- 判 达标 要看**真实命令能跑通**（现场跑一遍全量 eval），不是看文件里有个 eval 目录；证据 = CLI 命令表、e2e 测试、CI 配置里的 eval job。
- 3.1.2 与 6 可观测、8 CI 门禁联动但视角不同：本章查"门禁机制存在"，具体门禁阈值/灰度流程归 5.4/8，勿重复展开。
- 若被检方完全无自评基建：3.1 全 不达标 且**报告如实记"P2 自评层未评估"**，不因外部有第三方评测而豁免（外部卷子是 3.4 起的事，不是 3.1）。

## 3.2 测试集构成（五字段 / 四必备 / 配比规模）

**查什么**：卷子里每道题长什么样（五字段）、题的类型全不全（四必备）、数量配比够不够。**卷子质量决定评估上限——卷子烂，评分器再准也白搭。**

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.2.1 | 用例最小五字段 | 每条用例含：input / context / expected_output / expected_behavior / **forbidden_outputs**（禁止输出——防"答对了但用了不该用的路径"） | 缺字段，尤其无 forbidden_outputs（只有该做什么、没有不该做什么） |
| 3.2.2 | 四类内容必备 | 成功路径 / 边缘情况 / 对抗输入 / **历史失败**四类都有覆盖 | 只有 happy path；无反例集（从"应该发生"单侧建用例） |
| 3.2.3 | 来源与真实性 | 用例采自**真实用户输入/生产 issue**；冷启动合成用例须人工抽检 ≥20% | 全凭想象编任务，脱离真实工作场景 |
| 3.2.4 | 任务明确无歧义 | 任务描述带参考解且可复判：**两个领域专家应得出一致判定**；描述歧义即评估噪音被当缺陷处理 | 任务含混，专家各判各的；"0% 通过"不查任务本身是不是坏了 |
| 3.2.5 | 规模与配比 | 按阶段规模：**试点 ≥100 / 生产 ≥500**（20-50 可起步开跑）；配比：**边缘 20-30%**、**拒答+干扰题 5-15%** | 总量 <50 且无边缘样本；或纯简单样本充数 |
| 3.2.6 | 无训练/开发数据混入 | 测试题与训练/开发/调参数据严格分离 | 在训练/开发数据上评估（准确率虚高 6-40%） |

**检测注意事项（3.2）**：
- **forbidden_outputs 是最容易被省略的字段**，却直接对应"结果对但走了危险捷径"这类核心反模式——3.2.1 缺它即 警示，与"任务有效性（捷径不可达）"同旨。
- 合成/生成类用例必须有人工抽检记录（抽检率、抽检结果）可查；"冷启动合成"不可无限期当借口。
- 本章判"卷子齐不齐"；测试集实际跑出的难度分布与衰减（题是否有效）见 3.7，目标合格线见 5。

## 3.3 风险样本六类与历史失败沉淀

**查什么**：卷子不止要"会做的题"，还要"会考砸的题"——六类风险样本覆盖 + 历史失败沉淀。只测简单样本的卷子测不出 Agent 的抗风险能力。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.3.1 | 风险样本六类覆盖 | 六类风险场景各覆盖：**标准成功 / 歧义 / 证据冲突 / 权限边界 / 失败超时 / 成本时延** | 只测标准成功，无歧义/边界/冲突/失败/成本类样本 |
| 3.3.2 | 权限与越界样本 | 有"该拒绝时拒绝/越权操作拦截/边界权限"类测试 | 无任何越界/拒绝场景（权限检查在 7，但卷子需含相应题） |
| 3.3.3 | 失败与超时样本 | 有工具失败/超时/恢复场景；有"失败后能否正确降级/重试/求助"用例 | 假设一切永远成功 |
| 3.3.4 | 历史失败沉淀机制 | 生产/真实失败**能回流沉淀**成回归用例（Given/When/Then 格式）；事故到用例有落点 | 数据集静止不更新；事故复现了才发现没用例 |
| 3.3.5 | 回归防倒退 | 真实失败样本加入后能持续跑回归，防止"修 A 坏 B"；任何一题退步先不部署 | 失败样本不进回归，修完就丢 |

**检测注意事项（3.3）**：
- 六类风险样本并非六类全部必现于任何项目（如无权限模型项目可少测权限类），但**判"齐"要逐类说明覆盖或说明为何不适用**，不允许笼统说"有"。
- 历史失败沉淀（3.3.4）与 6/8 事故复盘、7 安全红线联动：这里是"沉淀物进卷子"这一环，另一侧是"事故复盘机制"，勿混写。
- 只放简单样本、无边缘、总量 <50 = 明确扣分反模式（3.3 配套查）。

## 3.4 基准与基线三件套（do-nothing / cheat / oracle）

**查什么**：光有题还不够——必须有对照基线证明"这套卷子真能测出能力差"。**do-nothing 得分非零 = 卷子效度不合格**。没有基线三件套，任何自报分数都不可信。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.4.1 | 基线三件套是否跑过 | **do-nothing（什么都不做）/ cheat（改测试、撞默认、走捷径）/ oracle（给答案）** 三条线都跑过并记录分数 | 没跑任何基线，直接报 Agent 分数 |
| 3.4.2 | do-nothing 分数 | do-nothing 得分**约等于 0**（非零即判结果效度不合格） | do-nothing 竟能通过任务（卷子存在"什么都不做也能拿分"的漏洞） |
| 3.4.3 | cheat/捷径检测 | 无"改测试文件/撞默认值/利用环境漏洞刷分"路径；测试文件安全存储，**与 Agent 可写区隔离** | agent 能覆盖测试文件伪造通过；有捷径绕过真实能力 |
| 3.4.4 | oracle 上限对照 | 有 oracle（给答案/理想上限）对照，说明卷子的理论上限 | 不知卷子上限，Agent 得分无法判断是真好还是卷子简单 |
| 3.4.5 | 披露义务 | 做不到完美效度时，**披露已知缺陷与误估方向（高估还是低估）**，作为报告合格项 | 隐瞒已知漏洞不披露 |

**检测注意事项（3.4）**：
- 基线是**卷子的标定**，不是 Agent 对比的"对手"：3.4 全部判据都指向"分数可不可信"，与"Agent 本身强不强"无关。
- 若项目自报分数缺三件套背书 到 一律按"未证实"降级处理（9.2 证据分级），即使分数再高也不当结论引用。
- ABC 43 项整体可作"深查附件"（检被检方自评体系本身可信度的第二把尺子，第一把是 Anthropic 三类评分器）；本章只落 3.4 主干，深审查附件留给 L3。
- **"不可能任务"要主动设计进卷子（tau-bench 的正确用法）**：**tau-bench**（Shunyu Yao 等，**arXiv:2406.12045，ICLR 2025**）在 airline 分区**故意设计了 38% 的"无法解决"任务**（retail 分区 6%），专门考察 Agent 能否识别"这事做不到"并正确放弃/转人工，而不是硬编一个结果。这正对应 3.2.2 对抗输入与 3.3 风险样本里的"该拒绝/该转人工"题。
  - **引用纪律（易错点）**：这 38% 是"**不可解任务的占比**"，**不是**"do-nothing 基线的通过率"。二者含义相反——前者说明卷子设计得好，后者才说明卷子有漏洞。**混用会把优点写成缺陷**，引用时必须写明是哪个。
  - **可借用的另两件硬货**：（1）该文判分方式是**比较对话结束时的数据库状态与标注的目标状态**——即"有副作用任务以最终状态判成功"这一口径的原始出处；（2）**pass^k**（k 次全部成功才算过）由此文提出，见 3.6.4。
- **cheat 防线的现实性（测试文件是最肥的攻击面）**：凡"Agent 写代码 + 跑测试判分"的评测形态，Agent 修改或覆盖测试即可伪造通过。**SWE-Lancer**（OpenAI，**arXiv:2502.12115**；1400+ 个来自 Upwork 的真实自由职业软件工程任务，任务总价值约 100 万美元，**按端到端测试判分**并折算金额）是这一形态的代表——判分完全依赖端到端测试，故测试资产的保护是被其形态本身逼出来的硬要求。
  - **判据落法**：测试文件须**只读挂载 / 独立目录 / 与 Agent 可写区隔离**，评测结束后做完整性校验（哈希比对）；检出 Agent 触碰测试文件即该次评测作废并记 不达标。

## 3.5 污染检测与可复现性

**查什么**：分数要能信，先过两道闸：**题没被剧透**（污染检测）、**分数能重跑复现**（环境冻结）。记忆类/长程类基准已被证明可刷（Zep 自报 84%到复测 58-75%），自报分数不直接采信。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.5.1 | 测试集防污染 | 测试集未进入模型训练/上下文；有检测机制（**6-gram 或整句重叠、Jaccard >0.8 记重叠**；CoDeC：干净 <60%、污染 >80%） | 公开题库直接自测无检测；评测题已可能在训练语料里 |
| 3.5.2 | 时间切分与改写防护 | 新题用发布时间切分（后于训练截止）；警惕"语义改写规避检测"型污染 | 只做字面去重，被改写型污染穿透 |
| 3.5.3 | 自报分数不采信 | 厂商自报分须有第三方复测/公开脚本；声明复测记录 | 只信厂商自报（Zep 84%到58-75% 打脸案例） |
| 3.5.4 | 环境冻结与可复现 | 环境版本冻结（镜像/站点/依赖/模型版本**可重跑**）；同代码两次得分可归因 | 环境漂移把正确行为判错；依赖浮动结果不可复现 |
| 3.5.5 | 分数绑定版本 | 分数与 harness/评测代码版本绑定；记录评测资产版本；同模型换 harness 波动 10-20 点属常态，不横向挪用 | 分数无版本可溯，改评测后新旧分混用 |
| 3.5.6 | 权重口径版本化 | 总分/权重/能力剖面口径写进文档并版本化 | 改了权重排名就换人（SuperCLUE 事件），旧结论无法解释 |

**检测注意事项（3.5）**：
- 污染检测的"层次"要挑明：外部评估方拿不到训练语料，现实可行是**灰盒三招**（发布时间切分造新题 / 语义等价改写对照 / CoDeC 置信度反差），全白盒检测（查训练语料重叠）仅在能访问训练数据时可用——判据按能力分层写，不苛求白盒。
- "分数能复现"最小验收动作：**现场重跑一次自评命令，两次结果一致**；做不到即记"不可复现，分数存疑"。
- 污染检测量化阈值（6-gram/Jaccard/CoDeC）写报告时标"参考口径（待复核）"——检测工具本身在真实多阶段训练下可靠性有限（公开文献常见结论）。
- **环境漂移是基准侧的已知硬伤，不是假想风险**：**OSWorld**（**arXiv:2404.07972，NeurIPS 2024**，369 个覆盖真实桌面与网页应用的计算机任务）依赖真实网站与在线服务，**这类"打真实外部环境"的基准天生随时间漂移**。其官方后续推出的 **OSWorld-V2** 专门建立 **"benchmark release + 可复现固定版本"** 机制（如 `osworld-v2-2026.08.08` 固定发布版），并明确建议"要用受支持的 release，而不要用浮动的最新版"——即**"没有冻结发布版就无法复现"已是官方承认并着手解决的问题**。
  - **判据落法**：不要求被检方"永不漂移"，而要求**评测环境具备可复现的冻结方式**（固定镜像 / 固定发布版 / 依赖锁），且能给出"上次跑"与"这次跑"的版本号。
  - **引用纪律（易错点）**：网传"OSWorld 46 个任务中 13 个已坏"一类**具体数字未能回源核实，禁止作为判据数字引用**。说明环境漂移风险时改用上列"官方已发布冻结版本机制"这一可核事实，或只作定性描述。

## 3.6 评测分层与节奏（smoke / regression / safety / benchmark）

**查什么**：评测不是一把跑完，要有分层（冒烟/回归/安全/基准）与节奏（PR/日/周/实时）。不同改动跑不同层，快慢搭配才养得起。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.6.1 | 分层存在（四类） | 有分层概念：smoke（快速冒烟）/ regression（回归防倒退）/ safety（安全回归）/ benchmark（完整基准）至少各有所指 | 只有一把梭全量跑；不分能力集与回归集 |
| 3.6.2 | 不同改动匹配不同层 | PR 前跑回归（小集快速）/ 完整 benchmark 每日或按版本 / 安全用例实时每 step / 上线前后核心回归 | 任何改动都全量重跑（太慢养不起）或都不跑（裸奔） |
| 3.6.3 | 冒烟速度与回归门槛 | 冒烟集小快（几十条级）能秒级~分钟级跑；回归有门槛值（如 pass@8 ≥80%、judge 均分 ≥4.0/5），"跑了不算过" | 冒烟也要几十分钟；无门槛"跑了就算过" |
| 3.6.4 | 双 k 同测 | **pass@1 与 pass@k（或多次试跑）同报**；不单次运行定论（非确定性处理） | 只报单次 pass@1；报 pass@k 却不报 pass@1 |
| 3.6.5 | 评测结果进决策 | 评测分数影响发布/门禁决策（不进 CI 的评测=摆设）；没通过不部署 | 指标不影响任何门禁，跑了白跑 |

**检测注意事项（3.6）**：
- 分层判"齐"看**实际调度配置**（CI 文件/脚本里的分层 job），不是口头说"我们有分层"。
- 双 k 的 k 值语义须写明：**pass@k**（k 次中至少一次成功）与 **pass^k**（k 次全部成功，用于客户可靠性）**方向相反**——报告须写明用的是哪个，勿混（地图 5.2 双 k 口径联动）。
  - **出处与分工**：**pass^k 由 tau-bench（arXiv:2406.12045）提出**，原文用它衡量"行为在多次试验中的可靠性/一致性"，即"客户能不能指望它次次都成"。故**对外/对客承诺场景以 pass^k 为准，探索能力上限场景用 pass@k，两者都报**。
  - **为什么必须双报（实证）**：tau-bench 实测 gpt-4o 单次成功率 <50%，而 retail 分区 **pass^8 <25%**——单次分与可靠性差一倍以上。只报单次的报告不可信。
- 安全层（safety）的深度内容归 7（攻击库入 CI 等），3.6 只判"有安全回归这一层、跑不跑得动"。

## 3.7 难度递进与能力衰减评估（探能力边界）

**查什么**：真本事要拉到难度阶梯上看——题分级、Agent 随难度/步数/干扰上升的表现衰减成曲线，才能看到能力边界在哪。单测简单题看不出能扛多难的活。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.7.1 | 难度分级存在 | 任务按难度分层（如 BFCL simple到multiple到parallel到irrelevance；GAIA L1到L3）；**分难度单报**不混成总数 | 所有题一锅煮，只报总成功率 |
| 3.7.2 | 能力衰减可测 | 有"随难度/步数/干扰上升的表现"衰减记录：**难度递进下降率**（从 L1到L3 掉多少）；步骤数与正确率关系可看 | 只有最终总分，无法回答"多难就不行了" |
| 3.7.3 | irrelevance 类负样本 | 有"该不该调用/该不该做"的判断类样本（需拒绝时是否拒）；不只测"能做"还测"该不做时不做" | 全是"要做对"的题，无"不应做"的题 |
| 3.7.4 | 能力边界与饱和 | 能识别饱和（100% 通过率=只剩防回归无改进信号）并补更难任务；能力剖面图/逐项优劣而非单总分 | 套件全饱和还当能力证明；只看总分掩盖弱项 |

**检测注意事项（3.7）**：
- 衰减评估判"可测"看**有没有按难度/长度分层的报告输出**（Level-wise Accuracy、按步骤长度分层统计），不是有没有画过一张图。
- 3.7 是"探边界"性质：若被检方只做功能回归不探能力边界，判 警示 并说明——除非其档位（1）本就只需回归级保障。
- 与 2.4 规划/长任务联动：步数相关衰减（几十步丢目标）的 Agent 行为本体在 2.4.5 判，这里判"卷子有没有把步数作为变量测"。
- **能力难度轴的现成基准映射（题源地图，参考口径，单源待回源）**：规划类卷子可按"任务分解 / 工具选择 / 中间步骤验证 / 动态重规划"四子维度分别对应现成题源（PlanBench/MINT / Gorilla / AgentBoard（Progress Rate）/ ScienceAgentBench）；工具类卷子按调用深度演进判断覆盖到第几级——单工具（BFCL）到 顺序多工具（ToolBench）到 并行/嵌套（NESTFUL）到 动态工具发现（APIBench）。用途=**查卷子难度轴与覆盖深度够不够、该用什么现成题源**，非新增硬判据；引用前须回源（单源）。

## 3.8 评估资产治理与闭环（评测资产的生命周期）

**查什么**：卷子不是做完一次就死。失败回流、饱和监控、owner 维护——**评估资产本身要当"活产品"养**，否则一次交付即死亡，越用越失效。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 3.8.1 | 失败回流闭环 | 生产/真实失败**沉淀回数据集**（去识别化）；灰度失败样本回流 | 数据集静止不更新；失败不回流 |
| 3.8.2 | 饱和监控 | 识别 100% 通过率套件并**持续补更难任务** | 全是已饱和任务还当能力证明 |
| 3.8.3 | 套件有 owner 维护 | 评估套件有 owner、随功能演进维护；评测代码纳入版本管理 | 一次性交付不再看；套件无人负责 |
| 3.8.4 | 评测与生产环境分离 | 评测环境与生产隔离（不污染生产/不被生产干扰）；mock/模拟环境说明 | 评测直接打生产库；或评测依赖生产不稳定环境 |
| 3.8.5 | 评估资产文档化 | 评测用途/局限/更新日志可查（卷子能解释自己测什么、不测什么） | 卷子无文档，后人不知能信几分 |

**检测注意事项（3.8）**：
- "回流"判据看**回流路径真实存在**：失败样例到（去识别化）到进数据集到重跑有记录，四环缺一不算闭环。
- 3.8 与 2.7 反思沉淀区分：2.7 是 **Agent 自身**经验沉淀，3.8 是**评估资产**的维护闭环——前者入 Agent 记忆/行为，后者入评测套件。
- 评测资产 owner 与 8 发布 owner、6 观测 owner 可为同一人或机制，但职责要可指认，不允许"有东西没人管"。
