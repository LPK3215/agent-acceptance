## 7.1 最小权限与授权模型（只给刚刚好的权限）

**查什么**：权限是安全第一闸门。核心口径一条：**Agent 权限 ≤ 请求者权限**（模型动作超过请求者权限 = 上线阻断形态）。往下拆：身份可归因（一 Agent 一 ID）、读写分离、临时凭证、授权边界三分类书面化、权限可回收。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.1.1 | 权限上界 = 请求者 | Agent 实际权限**不超过**触发它的用户/角色权限；逐工具权限 + 白名单 + 参数校验 + 写操作审批齐备 | 模型动作超过请求者权限；Agent 可自行提权触达更高级别资源 |
| 7.1.2 | 身份独立与归因 | 每个 Agent/会话有**独立身份标识**（一 Agent 一 ID），动作可归因到"哪个 Agent + 代表谁 + 何时 + 调了什么" | 多 Agent 共用身份/凭据；动作无法归因（责任缺口） |
| 7.1.3 | 读写分离 | 读类与写类权限分离；读场景不附带写/删能力；写操作走单独通道 | 一个通用权限全开读写删；读工具被用于篡改 |
| 7.1.4 | 临时凭证与最小留存 | 敏感资源用**临时凭证/短期令牌**，用完即失效；无长期明文密钥写死 | 长期密钥写死在配置/代码；凭据可被模型输出或工具带走 |
| 7.1.5 | 授权边界三分类书面化 | 操作按"全自动 / 半自动需人工确认 / **绝对禁止触碰**"**三分类书面化**并落成配置（与 7.4.1 触发点表同源） | 无三分类；"绝对禁止"类仅口头约定、运行时仍可达 |
| 7.1.6 | 权限可收敛可回收 | 有权限变更/回收流程（人员离场/场景结束/角色变更即收回）；超权限运行可被审计发现 | 权限只增不减；无回收机制 |
| 7.1.7 | 服务端身份与密钥注入 | 租户/用户身份由**系统服务端注入**（tenant_id/user_id），**模型不控角色与权限**；密钥入 secrets manager、不进 prompt/代码；模型调用以服务端注入的身份发起，不自带凭据 | 模型自行决定以谁的权限调用、或把密钥写进 prompt/代码（混淆代理人/confused deputy 风险） |

**检测注意事项（7.1）**：
- 与 2.5 分工：2.5 判"接入层本体质量（选型/参数/诚实性/失败重试）"，**权限/鉴权/最小权限/敏感工具锁定归本章**——勿在 2.5 重复判权限。
- 7.1.1 的提权路径要**实测**（最小用例验证"代表用户执行"不能调用其无权接口），不能只看权限配置声明；此条与 Agent Card #2 证据门槛同源。
- 7.1.5 的三分类即"决策边界书面化"：全自动/半自动/绝对禁止哪类都要落到代码层（白名单、审批闸门、硬阻断），否则纸面分类等于没有。
- 7.1.7 是"权限上界=请求者"的工程落地：光写"权限不超过用户"不够，必须**由服务端注入身份、模型不可自行指定调用者**——否则模型可通过伪造 tenant_id/user_id 越权（混淆代理人攻击）。密钥同理：入 secrets manager、绝不进 prompt/代码（与 7.2.6 供应链可信、7.6.4 脱敏联动）。

## 7.2 工具治理（工具不是"能接就能调"）

**查什么**：工具侧安全核心不是工具能力本身，而是治理：**白名单准入、schema 强校验、风险分级、危险操作管控、沙箱隔离、供应链可信**。主轴——白名单管"能不能调"（准入），沙箱管"高危调用在哪个笼子里跑"（损害半径），两者配套才完整。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.2.1 | 工具白名单准入 | 工具一律走**白名单**注册接入，新工具接入有审批流程 | 任意工具可被运行时动态加载/即时调用 |
| 7.2.2 | schema 与参数强校验 | 工具按 **schema 校验**（类型/必填/取值范围/格式），非法参数在调用前被拦截 | 参数不过校验直接透传；编造参数可被执行 |
| 7.2.3 | 风险分级 | 工具按风险分级（普通读/普通写/高危写、删/代码执行/网络外联），分级决定准入与审批门槛 | 不分级：危险工具与只读工具同权同门 |
| 7.2.4 | 危险操作管控 | 删除/支付/外发/代码执行/网络出口类危险操作有**额外闸门**（二次确认/沙箱/超时锁/双人复核） | 危险操作与普通调用一样直接执行 |
| 7.2.5 | 沙箱隔离（损害半径） | 高危/不可信调用在**沙箱/隔离环境**执行，损害半径受限；沙箱隔离强度与部署后端匹配（防"用了沙箱=固定隔离"幻觉） | 高危调用直连宿主/生产环境执行 |
| 7.2.6 | 工具来源与供应链可信 | 接入的 MCP/插件/工具来源**可审计**（发行方/版本/变更可查）；第三方工具过安全扫描或公开安全评分；关键第三方组件做**声明与实际行为一致性核验**（文档称只读/不联网，代码审计或实测发现外发/写操作即投毒信号） | 从不经审核的来源拉工具即接即用（工具投毒/供应链入口） |

**检测注意事项（7.2）**：
- 与 2.5.3 分工：2.5.3 判"按 schema 填对参数"（会调），7.2.2 判"非法参数在调用前被系统拦截"（准入校验）——前者是行为质量，后者是安全管控。
- 沙箱此处指**权限面隔离**（损害半径控制），不是 2.12 harness 运行时元件本体；隔离强度必须与部署后端匹配，固定 microVM 不等于 默认安全。
- 7.2.6 与 MCP 生态强相关：MCP server 来源评分（如 awesome-mcp-security 一类公开安全评分源）可作为现成检查依据。
- **组合权限红线**：Agent 若同时具备"读敏感数据 + 改状态 + 发消息"三类能力，须整体按高风险系统处理（单类普通、组合即高危）——权限判点不只看单个工具分级，须看能力组合的累积风险面（与 7.1.5 三分类、7.4.1 触发点表联动）。

## 7.3 注入与内容隔离（上了当也干不了坏事）

**查什么**：提示注入防不干净是常态，所以**防线必须挪位**——不赌"模型不上当"，而要保证"被骗的模型也没权限干坏事"。查内容分层、间接注入防护、输出护栏、GAP 双轨（文本层拒答 不等于 工具层安全）、污染可回滚、越狱回归。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.3.1 | 上下文分层与 untrusted | 系统指令/用户输入/工具返回/检索内容**分层**；外部内容默认 untrusted；工具返回只作数据、不允许覆盖任务目标与安全策略 | 检索/网页/文档内容可改写系统指令或安全策略（上下文污染） |
| 7.3.2 | 间接注入防护 | 工具读入的外部内容（网页/文档/邮件）中的指令**不被当作命令执行**，只当数据处理 | 打开一个网页/文档即触发其内嵌指令（间接注入最高危场景） |
| 7.3.3 | 输出护栏 | 输出前有内容安全过滤/护栏（违规内容拦截）；无输出护栏时**显式记录**（策略绕过=0 基线） | 无任何输出过滤；绕过策略仍有输出通道 |
| 7.3.4 | GAP 双轨检测 | 安全用例**双轨测**：既测文本层拒答，也验证工具调用层真不执行（声称拒绝却仍执行禁止动作 = 不达标） | 只测"嘴上拒绝"；不验证工具层（文本对齐 不等于 工具层安全） |
| 7.3.5 | 记忆/上下文污染可回滚 | 记忆/上下文被污染后**可回滚/可清除**（与 2.6.4 记忆可管理、7.6 数据治理联动） | 污染一旦写入永久生效、无法清除 |
| 7.3.6 | 注入/越狱回归样本 | 有注入与越狱回归用例库随版本回归（与 7.5.3 攻击库入 CI 同源），拒绝率与绕过率都有数 | 从未做过注入测试；或只做过一次性演示 |
| 7.3.7 | 输出结构化与执行边界 | 高风险动作**不由自由文本直接驱动执行**；输出结构化（summary/suggested_reply/risk_level/requires_human_review/executable_actions/blocked_actions）+ 显式标记执行边界，可执行动作与禁止动作明确分离 | 模型自由文本直接触发写库/外发/下单；无结构化执行边界（一句自然语言即生效） |

**检测注意事项（7.3）**：
- 与 2.2.3/2.6.3 分工：2.2.3 确认"污染面存在与否"（一票否决检出点），**注入隔离的对抗深检归本章**；2.6.3 判记忆防污染写入（本体侧），攻击深度测试走本章。
- **7.3.4 是关键判定，且有一手论文背书（可直接引）**：出处=**《Mind the GAP: Text Safety Does Not Transfer to Tool-Call Safety in LLM Agents》，arXiv:2602.16943**。该文核心结论即"**文本安全不会迁移到工具调用安全**"——在**全部六个被测模型**上均观察到"**文本层明确拒绝、工具层却仍执行了禁止动作**"的实例。
  - **判据落法**：安全评估**必须双轨**——既测文本层拒答，也验证工具调用层真的没执行。"声称拒绝却仍执行"是**独立失败类**，不能只看拒答文本判过。
  - **形式化定义（可直接写进用例设计）**：合取式如下——`GAP(x) = T-safe(x) 且非 TC-safe(x)`，其中 **T-safe = 文本层明确拒绝**、**TC-safe = 工具调用层安全（未执行禁止动作）**。即：现存多数基准只分别测"拒答率"与"危害完成率"，**缺的正是两者交集的正式度量**。用例集须**显式包含这一类样本**（声称拒绝却仍执行）。
  - **为什么这条不能省**：单轨（只测拒答率）会把这类失败**测成通过**——拒答率很高，但禁止动作照样被执行。这正是 7.3.4 列为一票否决级检查点的原因。
- 输出护栏在 demo 场景可不全配，但"无护栏"必须**显式记录在案**；生产/强合规场景按 不达标 处理缺项。
- 7.3.7 是"高影响动作不能由自由文本直接驱动"的工程落地：输出须结构化且**可执行动作与禁止动作显式分离**，模型一句自然语言不得直接变成副作用（与 7.4 人工确认、7.2.4 危险操作闸门配套——结构化输出只是第一道，真执行仍过审批/闸门）。

## 7.4 人工确认设计（关键时刻交给人）

**查什么**：HITL 不是"有个人看着"，而是**触发点明确 + 审批与动作绑定 + 留痕不可跳过 + 反伪人审**。尤其要防两种失效：每步都问造成的"同意疲劳"，以及假确认页面把人工闸门变摆设。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.4.1 | 触发点定义表 | 有**触发点表**：哪些动作必须人工确认（发合同/改报价/外呼/支付/删除/外发等），按风险分级映射（与 7.1.5 三分类一致） | 无触发定义，"人工确认"全凭感觉/事后补 |
| 7.4.2 | 审批绑定与不可跳过 | 关键动作强制人工确认**闸口**：确认动作有日志、有留痕、**不可跳过** | 审批可绕过/可跳过/可事后补记录 |
| 7.4.3 | 审批粒度与身份 | 审批与**具体动作/参数**绑定（批"发这份合同给 X"而非笼统放行）；审批人身份可验证 | 批一次全放行；审批人身份可伪造/批量代批 |
| 7.4.4 | 反伪人审/防同意疲劳 | 有人工确认防绕过设计：非真人不可批（反伪人审）；避免同意疲劳（步步都问 到 用户麻木 到 自动全放行） | HITL 被同意疲劳绕过；假确认页面通过即放行 |
| 7.4.5 | 审批证据与可恢复状态 | 审批时给出**完整证据 + 可恢复状态**（可撤销/可回滚路径），审批人看得清影响 | 只给"确认/取消"按钮，无证据、无可恢复路径 |
| 7.4.6 | 无人值守策略 | 无人值守/无人审批时段：高风险动作默认**拒绝执行**（fail-closed），不挂起不放行 | 无人审批时自动放行或无限挂起 |

**检测注意事项（7.4）**：
- 与 2.3/2.4 分工：2.3 判 Agent Loop 会不会停，2.4 判跨 session 停止/升级决策；**本章判人工闸门机制本身**（何时必须交人、人批了什么、能否被绕过）。判"该交人不交人"= 不达标。
- 7.4.4 双向都判：完全没有人工闸门是 不达标；每步都弹确认造成同意疲劳（致用户批量放行、闸门失效）同样是 不达标。
  - **出处（已回源）**：**Microsoft《智能体 AI 失效模式分类法 v2.0》**，新增 **7 个失效类别**，其中明确包含 **"同意疲劳（consent fatigue）导致 HITL 被绕过"**；另含 **MCP/插件滥用**、**计算机使用（computer-use）视觉攻击** 等。
  - **引用纪律**：引用时**必须注明版本号 v2.0**（该分类法仍在迭代，引用前关注 v2.x 更新并复核），不要把旧版条目当现行口径。
- 与 9.3 Agent Card #9 联动：人工审核项 2 分证据 = 风险分级 + 审批人 + 完整证据 + 可恢复状态，逐要素核对。

## 7.5 安全测试与红线（红线不松、攻击进 CI）

**查什么**：安全测试不是上线前跑一轮就完，要能**回归**。红线 = 一票否决、不平均掩盖；攻击发现 = 版本化入 CI；安全事故 = 写成必跑用例阻断发布。查四件事：红线清单 fail-closed、安全回归样本、攻击库入 CI、红线结果独立判。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.5.1 | 红线清单与一票否决 | 安全红线**书面化**并接 fail-closed 表（策略绕过/越权/审计缺失/跨租户泄漏/凭据暴露/不可逆高影响无确认 + 触发后阻断）。脚手架型套附录 B.1 即本点达标 | 无书面表（口头/系统提示/gitignore 不算）。平均加权稀释归 7.5.5，不在本点当 block |
| 7.5.2 | 安全回归样本集 | 有**安全回归样本集**（注入/越权/危险操作拒绝/禁用动作）随版本回归，不是只冒烟一次 | 无安全回归集；上线前手工试一轮即过。**G1 + 脚手架 = 警示，不得记不达标** |
| 7.5.3 | 攻击库入 CI（版本化） | 红队/攻击发现**版本化沉淀入 CI 攻击库**，可复跑可回归（无回归套件 到 旧漏洞随改动重现） | 红队测完即弃，攻击用例不沉淀不复跑。**G1 + 脚手架 = 警示，不得记不达标** |
| 7.5.4 | 事故 到 回归用例 | 安全/生产事故用 Given/When/Then **写成必跑用例并阻断发布** | 事故复盘完即止，无回归测试沉淀。**G1 + 脚手架 = 警示，不得记不达标** |
| 7.5.5 | 红线结果独立判 | 安全回归结果**独立报、独立判**，不进平均分被稀释；红线项不过 = 该层评估不通过 | 安全分混入总分，绕过策略仍得"良好总分"。G1 + 脚手架无攻击回归套件时本点记警示；**已有书面红线表却加权稀释仍按 7.5.5 / 10.1.2 block，不因脚手架豁免** |
| 7.5.6 | 红队分级触发 | 按风险档配红队：高风险（生产/资金/隐私）有正式红队（含外部视角），低风险至少内部对抗测试，触发档位写清 | 从不红队；或高低风险一刀切无分层。**G1 + 脚手架 = 警示，不得记不达标** |

**检测注意事项（7.5）**：
- **门槛分层（按 G 档 + 子类）**：7.5 六个检查点对不同自主度档位和子类的项目要求不同，避免一刀切导致"全灭"：
  - **G1 + 脚手架型**：仅 7.5.1（红线清单书面化）作为**达标门槛**；7.5.2-7.5.6 判"警示"（应提供扩展位置或文档模板，不要求实际实现）。**缺 `tests/security/` 目录、缺攻击库、未做红队不等于不达标。**
  - **G1 + 应用型**：7.5.1-7.5.2 作为**达标门槛**；7.5.3-7.5.6 判"警示"（应有 CI 攻击库和红队分级，低风险至少内部对抗测试）。
  - **G3 + 应用型**：7.5.1-7.5.3 作为**达标门槛**；7.5.4-7.5.5 判"警示"；7.5.6 按风险档触发。
  - **G4 + 应用型**：7.5.1-7.5.6 全部作为**达标门槛**（高风险须正式红队含外部视角）。
  - **G3 + 脚手架型**：7.5.1 作为**达标门槛**；7.5.2-7.5.6 判"警示"（应在文档中提供安全测试框架扩展位置和红线清单模板）。
  - 口径说明：门槛分层不降低安全底线——7.5.1 红线清单对所有档位均为**达标门槛**（书面化 fail-closed 红线），差异在于安全回归样本/攻击库/红队等后续检查点按风险档递进。
  - **7.5.1 易混点（提示词不等于红线清单）**：系统提示里的"不要做危险操作"、开发流程文档里的"禁止跳步/禁止交付 demo"、`.env` gitignore、错误不回显密钥——都**不算** 7.5.1。达标必须是书面 fail-closed 表（策略绕过/越权/审计缺失/跨租户泄漏/凭据暴露/不可逆高影响无确认 + 触发后阻断行为）。脚手架型无此表即不达标，补件指向附录 B.1，不得用提示词软约束凑数。**无表 = 本章不达标并按 10.1.4 封顶原型，不是 10.1.2 block**；block 只给已有表却把红线加权稀释（7.5.5）。
- 与 3.6/4 分工：3.6 判"有 safety 回归层、跑不跑得动"，4.2 判安全类内容归哪类判法；**攻击库内容、红线清单与判分标准归本章**。
- 与 5.4 分工不重叠：5.4 定义门禁阈值与加权规则（硬门禁不可被平均掩盖），本章判红线**有没有书面化、攻击有没有回归、事故有没有回流**——5.4 是"线设在哪"，7.5 是"线有没有被守住"。
- 安全回归样本可参考公开基准起步，不必从零自造：**AgentHarm**（Gray Swan AI + UK AISI，**arXiv:2410.09024，ICLR 2025**）：**110 个明确恶意任务**（增强后 **440**），覆盖 **11 类危害**（欺诈/网罪/骚扰等）；**保留 30% 任务不公开以防污染**；已集成进 Inspect 框架；**评分以人类编写的评分标准为主**，仅窄子任务用 LLM 评分。
  - **指标两种表述并存（易错点，勿互指为错）**：论文正文用 **harm score（危害分）**，并专门区分"**非拒答情况下的危害分（non-refusal harm score）**"；中文解读常表述为"**合规率**（正确识别并拒绝）+ **攻击成功率**（越狱后仍能完成多步任务）"。**二者指同一套双指标设计**，引用时择一并注明另一种表述。
  - **为什么对本章有用**：把"拒答了"与"真的造成危害"**分开统计**，正对应 7.3.4 双轨与 7.5.5"红线结果独立判"——照此设计用例可避免"拒答率很高所以安全"的假象。
  - **同类基准（可选起步源）**：SafeArena（250 任务/BrowserGym 真实浏览器/ARIA 四级风险规则）、ToolEmu（144 例/LLM 模拟工具执行/9 类风险）、R-Judge（569 例/测"模型判断交互记录中安全风险的能力"）。
- 微软分级红队口径（高风险正式红队、低风险内部红队）作参考框架，具体档位按 1 定档结果套。
  - **出处（已回源）**：**Microsoft《在 Windows 上开发负责任的生成式 AI 应用》**，官方页 [learn.microsoft.com/zh-cn/windows/ai/rai](https://learn.microsoft.com/zh-cn/windows/ai/rai)。原文分级要求：**使用 LLM 的高风险系统须正式红队（且须从组织外部招募专业红队）**；**低风险非生成式系统至少内部红队**；模型评估部分另要求**模型卡 + 人工逐步测试**。
  - **判据落法**：7.5.6 触发档位照此分——**高风险（生产/资金/隐私）要求带外部视角的正式红队，自评不成立**；低风险至少内部对抗测试。
- **验收侧快速三问（采购/对外交付场景尤其好用，可直接当提问清单）**：（1） 是否支持**按工具 / 按数据范围 / 按操作类型**三档收敛权限？（2） 敏感操作有无**人工审批钩子**？（3） 日志是否**完整可导出**？
  - 三问分别对应本章 7.1（权限）/7.4（人工确认）/6.4（审计可导出），**问不出具体答案即按对应判点记缺失**，不接受"我们支持权限管理"这类笼统回答。
  - 另一组可选框架（腾讯云 AI Agent 安全中心四功能）：**资产可视 / 行为可溯 / 运行可控 / 供应链可信**——可作面向业务方说明时的通俗表述，判据仍回本章各节。
- **外部风险框架对照（OWASP Agentic AI Top 10，2026 版）——用于查漏，不新增检查项**：本章六面可与 OWASP GenAI Security 项目《Top 10 for Agentic Applications》（**2025-12 发布，编号 ASI01-ASI10**）逐项对表，检验风险面有没有漏：

  | ASI | 风险（原文名） | 本章落点 |

## 7.6 数据治理与数据生命周期（数据从生到死都受管）

**查什么**：知识/记忆/数据库/日志**同受管**，不是只管用户库。查数据归属清单、保留期与清理、删除与遗忘、脱敏与最小化、跨租户隔离、审计闭环——安全合规 SLI（策略绕过=0、审计完整 100%）要在数据层可数可证。

| 检查点 | 查什么 | 达标信号 | 不达标信号 |
|---|---|---|---|
| 7.6.1 | 数据归属与清单 | 数据（记忆/知识/DB/日志）有**归属与数据清单**：存了什么、谁的数据、存在哪、谁负责 | 数据散落无清单，无人能说清系统里存了什么 |
| 7.6.2 | 保留期与归档 | 各类数据有**保留期/归档策略**（存多久、何时归档、到期清理）；可验证自动清理 | 无限期保留、只增不清 |
| 7.6.3 | 删除与遗忘 | 用户/租户数据可**删除/遗忘**（用户要求即删；与 2.6.4 记忆可管理联动） | 用户无法删除自己的数据（阻断形态） |
| 7.6.4 | 脱敏与最小化 | 敏感数据落库/落日志前**脱敏**（凭据/个人信息/密钥不落明文；与 6.2.4 快照脱敏联动） | 密钥/PII 明文入库、入 trace、入快照 |
| 7.6.5 | 跨租户隔离可验证 | 多租户数据**隔离经测试验证**（A 租户查不到 B 租户记忆/知识/DB）；隔离失效 = 跨租户泄漏 = 阻断 | 无租户边界；或隔离从未被测过 |
| 7.6.6 | 生命周期审计闭环 | 数据读取/修改/删除有**审计留痕**；策略绕过=0、审计完整 100% 作为 SLI 可计算可报告 | 数据无审计；策略绕过无人发现 |

**检测注意事项（7.6）**：
- 与 2.6/2.8/2.10 分工：本体章判"记忆/知识库/数据库**有没有**那套机制"（可查/可改/可删/权限边界），本章判**安全底线口径**——保留期设没设、删不删得掉、脱不脱敏、跨不跨租户、有没有审计闭环。本体问"会不会存"，本章问"存得安不安全、能不能删干净"。
- 与 6.2.4 分工：6.2.4 判"快照**有**脱敏机制"，**留什么/删什么/保留期归本章**。
- "用户无法删除自己的数据"是 Agent Card #3 的 0 分（阻断）形态，直接判 不达标，不进入"建议改进"讨论。

## 本章收口：安全底线判定与后续分诊

7 跑完，输出**安全判定表**：

1. **逐节结论**：7.1-7.6 每节 = 达标/警示/不达标，附缺项清单。
2. **红线触发项（fail-closed 列表）**：任一**行为**红线触发直接判本层不通过并进入 10 的 block 清单——模型动作超请求者权限（7.1.1）/ 危险操作无闸门或直连宿主（7.2.4-7.2.5）/ 外部内容可重写系统指令（7.3.1）/ 该交人不交人或审批可绕过（7.4.2）/ 有书面红线表却把红线加权稀释（7.5.5）/ 用户数据无法删除或明文裸存（7.6.3-7.6.4）。**无 7.5.1 书面表** = 本章不达标（封顶原型），不进入上列 fail-closed / block 清单。
3. **降级记录**：demo/未上生产场景可降级项（输出护栏 7.3.3）须在报告**显式豁免说明**，不豁免按 不达标 计。**全量红队 7.5.6 在 G1 + 脚手架不走“不豁免 = 不达标”**——按分层记警示；不得因未建红队目录把脚手架打成不达标。
4. **接 8 上线**：7 红线全绿是 8.2 上线检查的前置 Gate；沙箱隔离 + 审批门 + 可回滚 = 1.6 高档位强制加码项；8.3 失败隔离/回滚的权限面由本章供给。红线触顶时 8 直接不开查。
5. **接 5.4 口径**：安全合规 SLI（policy_escape_count、audit_completeness_rate）的**内容判定在 7 完成**（设没设线在 5，守没守住在本章）。
