# 全局地图（Global Map，章树全貌）

> **性质**：`agent-acceptance` 技能内的**全局地图 = 章树全貌**（穷尽"该检查的全部面"，答拆得透不透），非任何单章的"总结"。**本图与章正文平级同在 `references/` 下，不是入口与正文之间的第二层索引**；执行验收从入口 [SKILL.md](../SKILL.md) 的路由表点开章正文即可，不必先读本图。
> **什么时候才读本图**：（1）想先扫一遍全貌、看整套覆盖了哪些面；（2）核对某条检查面有没有家、覆盖有没有盲区；（3）维护扩容——新面入图先过下方"扩容三铁律"。日常按章执行时用不到它。
> **章正文如何回链**：各章头部"本章角色 = 全局地图 x 的展开正文"即回链到本图对应小节，供从正文反查全景。
> **扩容铁律**：图**只增不删**——穷尽面是它的使命，不靠删减控质量。但新面入图须过三关：（1）**通用**——对任意形态/技术栈/场景的 Agent 都成立，非单项目专属；（2）**公用**——其他章查同一条可直接回链，不造语义重复的面；（3）**可判**——能落成"查什么/判据/证据"而非感想。过不了三关的不叫"该查的面"，叫杂讯，不入图。

## 0. 分层速览索引表

> **与入口路由表的关系**：本表与 [SKILL.md](../SKILL.md) 的"章级路由索引"是**同一分层（P0-P3）的两种视图**，不设两套口径。执行选层以入口路由表为准（每行直达章正文）；本表是**全貌展示**（给通读/核对覆盖用），补"每层开查门槛与性质"一行。两表不同步修改会失真，维护时先改入口路由表，再回头对本表。
> 章（1-10）= **对象/流程轴**，答"检查面全不全"；层（P0-P3）= **使用轴**，答"这层要开查，被检方得先拿得出什么"。分层说明即写死**本层所需被检方提供物**。
> 层**不另建文档、不改章节编号**——正文一律按章落；"每层一册"只在交付时做导出视图，不是源头副本。
> 防误三句：（1） 层是全集，**不因"项目涉及不到安全合规"删层**；（2） 跑检查永远先过 1 定档，再按档位/形态决定后续层上不上场；（3） 1 天生是选层问卷，不是"足够了解才选层"，是最小定档。

| 层 | 名称 | 开查门槛：被检方至少拿得出 | 覆盖章 | 性质 |
|---|---|---|---|---|
| **P0** | 定档问卷 | 形态 / 技术栈 / 目标边界 / 成功标准 / 自主度（口答或文档即可） | 1 | 必经入口 = 选层问卷 |
| **P1** | 本体可查 | 源码 + 文档（不需专门评测资产） | 2 本体构成 | 默认必查主干（静态审查 + 行为用例） |
| **P2** | 评测资产 | 测试集 / 自评基建 / 判分口径 / 目标值 | 3 考卷、4 判分器、5 指标 | 拿不出该层即查不动 到 报告记"该层未评估"，不硬套 |
| **P3** | 运行与交付证据 | 可运行部署 + 观测 / 审计 / 上线 / 交付证据 | 6 可观测、7 安全底线、8 生产就绪、9 交付物 | 7 底线必查不可跳；9.6 业务六维按场景触发 |
| **收口** | 档位定论 | 以上各层结论齐 | 10 档位 | 档位 / 未证实项清单 / 改进回归 |

> **使用深度并存标注**（L1/L2/L3，另一视图）：**L1 必查主干**（约 P0+P1+7 底线 + 6/8/9 基础件，图裸跑够验八九成）；**L2 深化**（数字合格线 / judge 校准 / 反模式，判深时上）；**L3 专项触发**（对抗深检 / 合规对照 / 9.6 业务六维，场景触发才上）。两轴不冲突：P 轴管"这层需要被检方给什么才能查"，L 轴管"这次查多深、哪些触发"。

## 1. 项目定档与边界
### 1.1 是否真需要 Agent（过度设计四问：（1）是否必须跨多步完成 （2）是否需按上下文选工具 （3）错误操作是否可恢复 （4）新增成本风险有无业务价值支撑——规则/结构化抽取/搜索/普通 RAG 已够用时，Agent 只是过度设计、徒增风险成本）
### 1.2 载体形态（先定形态再定技术：形态不等于技术，Web 前后端分离 / 纯后端服务与 API / CLI / 桌面、IDE 插件 / 嵌入宿主应用 / 批处理无交互，均属"长成什么样"的形态切分；形态决定技术选型与启用哪些检查面——含前端才查交互呈现与 UX，纯后端查并发、鉴权、接口契约，CLI 查参数、退出码、TTY，不含 UI 的形态跳过前端面）
### 1.3 技术栈（形态定后才有技术选择：语言/框架/运行时/编排与多 Agent 形态/依赖的 LLM 与工具平台；技术只改判据"怎么写"不改"查什么"——检查断言行为、不锁实现，语言特有落点仅作附注）
### 1.4 目标与任务边界（做什么/不做什么/交付物/拒绝场景）
### 1.5 成功标准与验收口径（可测试）
### 1.6 自主度 / 角色分级与适用档位（G1 工具层只执行不决策 到 G2 助手层给建议人拍板 到 G3 协作者层对等分工 到 G4 自主体全自主；越接近决策端验收越严：全维评估+强监督+分级审批+可关停，高档位强制加码——审批门+可回滚+沙箱隔离；**另存外部对照尺**=用户角色轴 L1 operator 到 L5 observer，见 Feng/McDonald/Zhang《Levels of Autonomy for AI Agents》arXiv:2506.12469（华盛顿大学，Knight First Amendment Institute 出版，2025），两轴同向不同颗粒度，本图按 G 轴落格、不硬映射）

## 2. 本体构成（本体全景母图：认知核心+主体部件+资源供给，代码层判定齐不齐）

### 2.1 模型与认知核心层（Model Management）
#### 2.1.1 模型选型与供应商（哪家/哪个版本/为什么）
#### 2.1.2 模型版本管理（升级/回滚/多版本并存）
#### 2.1.3 推理参数固化（temperature 等是否写死、谁能改）
#### 2.1.4 换模型的护栏影响（升级认知不等于可拆护栏，全链路复测）
#### 2.1.5 模型调用成本与配额（预算/超限行为/降级）

### 2.2 上下文管理（Context Management）
#### 2.2.1 上下文窗口与预算（长度上限/占用监控/超限策略）
#### 2.2.2 截断与压缩策略（丢什么保什么/摘要是否可靠）
#### 2.2.3 上下文污染隔离（外部输入/检索内容不串扰决策）
#### 2.2.4 跨轮一致性（长任务中目标与约束不丢）
#### 2.2.5 会话持久化与恢复（重启/断点能否接上）
#### 2.2.6 敏感信息处理（上下文脱敏、不落明文日志）

### 2.3 自主执行循环（Loop）
#### 2.3.1 启动与触发方式（谁/什么事件启动：手动还是自动/触发条件明确）
#### 2.3.2 正常收尾与明确失败（做完了/做不成了都会停）
#### 2.3.3 死循环与失控防护（步数上限/超时/自锁）
#### 2.3.4 中断恢复与断点续跑（暂停后能否从断点继续，而非从头重来）

### 2.4 规划与推理落地
#### 2.4.1 任务拆解（大任务拆成有序可执行步骤）
#### 2.4.2 链式推理（先想后做、推理过程合理可查）
#### 2.4.3 计划执行与推进（拆出来的步骤真被执行完）
#### 2.4.4 动态调整（失败/变数时改计划而非死磕）
#### 2.4.5 长任务稳定（几十步不丢目标、不做无用功）

### 2.5 工具与技能接入层（Tool / Skill Use）
#### 2.5.1 技能管理（Skill Registry：技能清单与目录/可发现与按需加载/版本与更新/权限/与工具的分工——技能 = 指令文档+工具/资源打包的可复用能力单元，非单个工具）
#### 2.5.2 工具选型与注册（用什么/为什么/何时该换）
#### 2.5.3 调用参数正确性（按 schema 填对/无编造参数）
#### 2.5.4 结果消化与真使用（返回内容用于推进任务）
#### 2.5.5 调用诚实性（不编造调用/不谎报成功）
#### 2.5.6 失败重试与降级（换工具/降级而非卡死）

### 2.6 记忆机制实现（Memory）
#### 2.6.1 短期记忆保持（同会话关键信息不丢）
#### 2.6.2 长期记忆写入与检索（跨会话知识与偏好）
#### 2.6.3 记忆准确性与防污染（写入不串味/读出不错配）
#### 2.6.4 记忆可管理性（可查/可改/可删/可关）
#### 2.6.5 记忆参与决策（检索结果真被使用，非存而不用）

### 2.7 反思与自我改进回路（Feedback Loop）
#### 2.7.1 反思触发（失败/异常/不确定时是否主动复盘）
#### 2.7.2 反思质量（能否定位"错在哪、为什么错"）
#### 2.7.3 修正闭环（下一步行动因反思而改变，不重蹈覆辙）
#### 2.7.4 改进沉淀（经验是否落盘、可复现而非一次侥幸）

### 2.8 知识库与 RAG（Knowledge Base）
#### 2.8.1 知识来源与入库（哪些库/谁维护/版本）
#### 2.8.2 检索质量（召回/排序/阈值/重排）
#### 2.8.3 引用与溯源（结论带出处、可回查）
#### 2.8.4 知识更新与过期（更新周期/失效处理/未收录拒答）
#### 2.8.5 知识权限边界（谁可读/多租户隔离）

### 2.9 文档与内容解析（Document/PDF 解析）
#### 2.9.1 格式覆盖（PDF/Word/PPT/图片/扫描件/网页等）
#### 2.9.2 解析正确性（表格/公式/版式/OCR 质量）
#### 2.9.3 低质量源处理（识别不可靠内容到拒答或降级）
#### 2.9.4 解析管线可观测（耗时/错误率/失败重试）

### 2.10 数据与文件管理（Database & Files）
#### 2.10.1 数据库存取设计（schema/事务/连接管理）
#### 2.10.2 数据正确性与一致性（CRUD 后状态可核）
#### 2.10.3 数据权限与隔离（最小权限/租户边界）
#### 2.10.4 数据生命周期（保留期/归档/清理/删除）
#### 2.10.5 文件与文档组织（目录/版本/权限/路径安全）

### 2.11 状态与编排（Workflow/Graph/checkpoint）
#### 2.11.1 状态持久化（checkpoint 落点/频率）
#### 2.11.2 恢复与重放（崩溃后能接续）
#### 2.11.3 编排结构可控（Graph/Workflow 定义可见、可停）
#### 2.11.4 版本化运行（发布对象与运行版本绑定）

### 2.12 Harness 运行时八元件是否齐备（运行壳工程：上下文组装/工具执行/记忆访问/审计/限流等八元件是否真实接线，非框架自带即算）
### 2.13 多 Agent 协作与通信（适用多 Agent 系统；单体验收直接跳过）
#### 2.13.1 协作拓扑与角色分工（主从/对等/层级/职责边界）
#### 2.13.2 通信与共享状态（消息协议/上下文共享/一致性）
#### 2.13.3 冲突检测与仲裁（决定冲突时谁说了算）
#### 2.13.4 协作效率与开销（通信成本/冗余劳动）
#### 2.13.5 群体级失败扩散与隔离（单点故障/级联）
#### 2.13.6 群体记忆与分工持久化（成员记忆共享/各自保存，重启后仍在）
