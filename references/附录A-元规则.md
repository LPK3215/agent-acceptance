# 附录 A 元规则

> **本章角色**：[全局地图 附录 A 元规则](00-全局地图.md) 的展开正文。规范正文 1-10 是"查 Agent"的判据；本附录是**检查者自身的纪律**——A.1 先划界"**不评什么**"（Out of Scope，防检查范围无限膨胀、拿规范当万能尺），A.2 列"**不犯什么**"（反模式自查，出现任一条即扣分项），A.3 定"**证据从哪取**"（来源纪律，脏树不作被检方达标）。3/5/6/8/9/10 各章按"详见附录 A"联动的内容，其判据本体在此展开。
> **一句话**：查别人之前先管住自己——哪些对象本规范不接、哪些查法自己不能犯，读完本附录才具备"当检查者"的资格。
> **本章边界（防越界三句）**：（1） A.1 只判**对象范围**：本规范不评什么、为什么、该去哪评——对象一旦进入 A.2/正文范围，就按正文 1-10 查，本附录不再重复判据；（2） A.2 只判**检查者自身动作**：不是被检方的扣分项（被检方的反模式已在对应正文章节判），A.2 任何一条成立即对**检查者/验收报告**扣分并整改；A.3 同样只判检查者取证动作，不把脏树写成被检方达标；（3） 附录 B（脚手架型项目通用接入模板）是**随技能打包的实操参考**，为脚手架型项目提供红线清单模板、接入位置文档化示例和扩展位置文档模板，不增加判据，只提供可复用的参考物。
> **依据原则**：本附录判据全部自含、可直接执行；A.1 边界与 A.2 反模式均按"可判的动作/形态"表述，不写感想；文内数值/条款为参考口径（按 1 定档场景校准）。公开来源（模型评估反模式清单、Agent Card / 发布评分卡实务、SWE-bench 社区教训等）按名联网复核即可。
> **溯源参考（联网可检索，非本地依赖）**：A.2 六条反模式与下列公开实务同源可溯——"在训练/开发数据上评估导致虚高"（LLM 评测污染讨论，CoDeC/SWE-bench 教训）；"只放简单样本、总量 <50"（评测集规模实务经验线，多份开源评测指引）；"单指标定论"与"平均加权掩盖红线"（Agent Card 评分实务、质量 SLI-SLO 发布评分卡反模式）；"指标不影响门禁"（go/no-go 决策映射实务）；"无反例集、只从应该发生单侧建用例"（禁止输出 forbidden_outputs 字段、任务有效性"捷径不可达"口径）。以上按名检索即可。

## A.1 Out of Scope（不评什么）

**查什么**：给整套规范划**边界墙**——明确哪些对象**不在本规范验收范围内**、为什么、应去哪评。防止两类错用：（1） 拿本规范去验"模型强不强"这类不属于 Agent 应用验收的问题；（2） 该由别处（L3 专项 / 外部基准 / 组织治理）评的，硬塞进 L1 检查里假装查完。边界判断发生在 1 定档期，不在每章重复展开。

| 检查点 | 查什么 | 达标 正确判定 | 不达标 越界用法 |
|---|---|---|---|
| A.1.1 | 模型基座与训练质量 | **基座模型的能力、训练过程不评**：模型选择理由可查（2.1.1），但"这个模型本事大不大/训练得好不好"归模型评测（外部跑分、模型卡、乙类基准），不进 Agent 验收结论 | 拿"基座模型在某榜单分数低"判项目不合格；或把模型厂商评测当本项目验收证据 |
| A.1.2 | 纯 prompt / 无 Agent 形态 | 无多步自主执行、无工具选择、无状态循环的**纯提示词封装不按 Agent 验**：若 1.1 四问判"不需要 Agent"，其评测不属本规范对象（回传统 NLU/规则评测） | 把 chat-wrapper/纯 prompt 项目按 2-10 全套硬查，或反之跳过 1.1 直接套用 Agent 判据 |
| A.1.3 | 通用公平性/模型偏见议题 | 模型**固有偏见的社会性评估**（与具体 Agent 行为无关的通用公平性议题）不评：与本 Agent 任务相关的**行为层**有害/偏见输出仍按 7.3.3/输出护栏查 | 以"公平性属模型问题"为由跳过行为层有害输出检查；或反向承接全库通用公平性审计 |
| A.1.4 | 组织级合规认证 | ISO/IEC 42001 组织认证、SOC 2、治理委员会签核等**组织级/体系级**动作不评（L3 组织范围，8.7 收口）；产品级可验部分（9.5 GB/T 25000.51 就绪评测）仍在范围内 | 拿"组织在跑认证流程"充当本项目验收结论；或要求 L1 检查者替组织背书合规 |
| A.1.5 | 超出 1 边界的业务效果 | 1.4/1.5 明确圈外的功能/业务指标不评：边界墙在 1 定档时已立，后续层不越界补查（如"应拒绝场景"里表现差不算缺陷） | 检查者自行加戏查未定档功能；把边界外表现当失败记入报告 |

**检测注意事项（A.1）**：
- 边界墙是**双向**的：既防"不该查的硬查"，也防"该查的拿'这不在范围'挡掉"——判一条是否 Out of Scope 的标准是**它是否影响 1 已定档的目标与成功标准（1.5）**，影响则为范围内，不影响才是 Out of Scope。
- A.1 判定写进报告"检查范围声明"：本次验了什么、明确没验什么、没验的部分去哪评（外部基准 / L3 专项 / 组织治理）。范围声明是验收报告第一页内容（接 9.5 报告骨架），缺失即报告不完整。
- 与 10 联动：被检方拿"A.1.1 说模型不评"反驳检查者查了模型选择理由？不成立——2.1.1 查的是**选型决策合理性**（为什么选它、风险接不接受），不是模型能力本身，两者边界以"查的是决策还是本事"区分。

## A.2 验收者反模式自查（不犯什么）

**查什么**：检查者**自己**最容易犯的六个错——六条反模式，任何一条出现即扣分项，需自查自纠并写入报告。每条的判据在正文对应处已细化，这里给"反模式-症状-后果-正确做法"四联判定，供检查者在每次验收收尾时逐条过一遍。

| 检查点 | 反模式与症状 | 为什么扣分 | 正确做法（联动正文） |
|---|---|---|---|
| A.2.1 | **在训练/开发数据上评估**：拿进过训练语料或开发调参用过的题当测试集 | 分数虚高 6-40%，"测试通过"实际是"背过答案"，结论无预测力（3.5.1 污染口径） | 评测题与训练/开发/调参数据严格分离（3.2.6）；有 6-gram/整句重叠检测与时间切分（3.5.1-3.5.2）；做不到则该分数按未证实降级（9.2） |
| A.2.2 | **只放简单样本、无边缘、总量 <50**：全 happy path 充数，边缘/对抗/失败样本缺失 | 测不出真实能力落差；do-nothing 可能"通过"而不自知（3.4.2 口径） | 四类内容必备（成功/边缘/对抗/历史失败，3.2.2），风险样本六类逐类说明（3.3.1-3.3.3）；规模按阶段（试点 ≥100/生产 ≥500，3.2.5 参考口径） |
| A.2.3 | **单指标定论**：只看"成功率 90%"一个数就下结论，不看分型/失败模式/维度 | 掩盖结构性缺陷（同一失败模式占比高、特定输入类全挂），结论给不了整改方向 | 指标按维度分层报（5.1 口径、5.5 成本/质量/时延同报）；失败按模式归因分型（5.2）；结论档按合成协议走（10.1.4）而非单个分数 |
| A.2.4 | **所有指标平均加权掩盖红线**：0 容忍项（安全绕过/审计缺失/越权）混进平均分被稀释，总分"良好" | 红线被"其余都很好"翻盘——10.1.2 否决项优先原则被平均加权破坏 | 0 容忍层与可让步层分开（5.4.3）；加权分层而非平均（10.1.3）；安全结果独立报独立判（7.5.5），红线触顶即 block（10.1.2） |
| A.2.5 | **指标不影响任何门禁**：评测跑完就收工，分数与放行/回滚决策无关 | 评估是"展示"不是"门禁"，跑分再低照样上线——整套评估失去意义 | 指标绑定 go/no-go 决策映射（5.4 到 8.5）；不达标走 canary_only/manual_review/block；分数进 8.2 上线 Gate 与 10 结论档 |
| A.2.6 | **只从"应该发生"单侧建用例，无反例集**：只写期望输出，不写禁止输出/越权/捷径路径 | 漏掉"答对了但用了危险路径"这类核心缺陷；捷径不可达未验证（3.2.1 口径） | 每条用例带 forbidden_outputs（3.2.1）；成功路径外建反例/越界/拒绝场景（3.2.2、3.3.2）；安全侧回归含攻击样本（7.5） |

**检测注意事项（A.2）**：
- **自查动作本身要留痕**：每次验收收尾，检查者按 A.2.1-A.2.6 逐条过一遍，结论写进报告"检查者自查"节——"本报告无 A.2.1/A.2.3 情形；A.2.2 因试点阶段以 60 条起步已说明"一类；自查节缺失或空白即报告不完整（接 9.5 骨架）。
- 反模式判定是**报告级扣分**：出现任一条 = 该报告相应结论的可信度降档（联动 10.2 未证实处理）——不是把被检方整单判死，而是**该结论作废或降级重跑**；多条并发（如 A.2.1+A.2.3 同时）须重跑，不允许"补写说明"糊过去。
- 与正文反模式的分工：正文（3/5/7 等）判**被检方的系统有没有**那套机制与反模式；A.2 判**检查者这次验收动作本身犯没犯**。同一现象可能两侧都成立（被检方数据混入 + 检查者没查污染）——两侧分别记，不抵消。

## A.3 证据来源纪律（从哪取）

**查什么**：证据只认**被检根与本轮验收快照**。A.3 不是第七条反模式，不扩 A.2 六条清单。

允许：用户声明的被检项目根、定档记录第 8 项写明的工作区或指定 commit/tag。

禁止当作证据源（出现即检查者动作违规）：

- 技能仓库内夹带副本（fixtures、测试项目临时用、其中 `.venv`）
- 本轮声明之外的历史 `acceptance/` 目录
- 过期或未声明的 worktree
- 未纳入快照的 IDE / 助手未跟踪树

本轮写入的 `acceptance/` 是**产出**不是证据源。违反 = 相关结论降未证实或作废，**不得把脏树写成被检方达标**。

## 附录收口：检查者出师自检

跑完本附录，检查者应能回答四问并写进报告：

1. **范围声明**（A.1 输出）：本次验收的范围墙（验了什么 / 明确没验什么 / 没验部分去哪评）是否写清——写清才能防"验收报告被拿去当万能背书"。
2. **自查结论**（A.2 输出）：A.2.1-A.2.6 逐条自查结果与处置——无违规要声明、有违规要降级重跑或标注影响面。
3. **证据来源**（A.3 输出）：被检根、验收快照、本轮忽略的禁源是否写清；若用了禁源，相关结论已降未证实或作废。
4. **判据完整性**：所有进结论的数字都有正文判据背书、没有"未经正文任何判据直接当结论"的自造尺。

> 收口物即"检查者纪律页"，作为验收报告开篇的**前置章节**（先声明怎么查、再给查的结果），与 9.5 合规报告骨架、10 验收结论单配套使用。附录 B（脚手架型项目通用接入模板）为脚手架型项目的快速达标提供可复用模板，随技能打包，检查时可直接引用。
