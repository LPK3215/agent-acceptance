# agent-acceptance：AI Agent 项目的工程验收与定档

![版本](docs/assets/badges.svg)

`agent-acceptance` 是一份面向 AI Agent 与多 Agent 项目的工程验收标准，以 Agent Skills 技能包形式发布。它回答三个问题：项目**是否拿得出手、能否放得出去、应给予什么档位**。

本标准的评估对象是工程与证据，而非模型能力。全部判据自含于技能包内，任何第三方均可依据本仓库独立复核并得到相同结论。它不评价模型能力强弱，不代替第三方资质检测或带章检测报告。

## 档位体系

验收结论分为五档：

- `block`：当前放出去会出问题，禁止交付。整改后可复评、可升档
- `仅 Demo`：仅限演示场景
- `原型`：可用于原型验证
- `有限 Beta`：可在受限范围试用
- `生产候选`：具备对外放行条件

档位高低与监管风险相互独立。涉及资金、隐私、人身安全等敏感面的项目，无论档位结论如何，均须另行通过安全底线与证据等级的把关。

## 检查级别与使用方式

上述十章是完整的能力清单，但实际验收不会十章全上。技能提供四个检查级别，包含制，选高自动包含低——选一个级别即可开始。

| 检查级别 | 实际跑哪些章 | 适合什么场景 | 会拿到什么 |
|---|---|---|---|
| 轻度（初级检查） | 1 -> 2 -> 10 | 快速看骨架对不对 | 体检初判：哪些面达标、初步结论。缺材料的层记"未评估"并自动封顶 |
| 中度（中级检查） | 1 -> 2 -> 7 -> 10 | 想知道能不能上线、安不安全 | 轻度全部 + 安全底线判定 + 改进清单 |
| 重度（高级检查） | 1 -> 2 -> 3-5 -> 6-9 -> 10 | 要正式验收报告，合同 / 采购 / 上线用 | 第三方可复核的完整验收报告：含评测资产核验、运行可观测、交付证据链 |
| 自动（AI 全扫后自选） | AI 先读项目再选级别 | 不确定该查多深，让 AI 看过项目再决定 | 同选定级别，附带 AI 选级别理由说明 |

> **包含关系**：重度包含中度包含轻度。选了中度 = 自动跑轻度的全部 + 加 7 章；选了重度 = 自动跑中度的全部 + 加 3-6/8-9 章。自动级别不是第四种内容，而是让 AI 替你从前三个级别中选 / 交叉。

技能加载后，复制对应级别的开场白给 AI 助手即可开始。第 1 章定档问卷以问答形式进行，无需事先阅读正文。完整执行说明见 [SKILL.md](SKILL.md)。

### 轻度（初级检查）

适用场景：快速看看这个项目骨架对不对，哪些面达标、初步结论如何。

> 请使用 agent-acceptance 技能，技能来源仓库为 https://github.com/LPK3215/agent-acceptance，对项目做轻度检查。先执行第 1 章定档问卷，再跑第 2 章系统组成，最后进第 10 章出结论。缺材料的层记"未评估"并自动封顶，不拖垮结论。

会拿到：骨架初判报告，含定档记录、系统组成判定表、初步结论单。单次会话完成。判据细节可读 [01 范围、形态与档位](references/01-范围、形态与档位.md) 与 [10 验收结论与档位](references/10-验收结论与档位.md)。

### 中度（中级检查）

适用场景：想知道能不能上线、安不安全，出结论 + 改进清单。

> 请使用 agent-acceptance 技能，技能来源仓库为 https://github.com/LPK3215/agent-acceptance，对项目做中度检查。先执行第 1 章定档问卷，再跑第 2 章系统组成与第 7 章安全底线（红线必查），最后进第 10 章出结论。安全不达标的项进改进清单，给出整改优先级。

会拿到：在轻度全部产出的基础上，增加安全底线判定表与改进清单。判据细节可读 [07 安全与权限底线](references/07-安全与权限底线.md)。

### 重度（高级检查）

适用场景：要正式验收报告，合同 / 采购 / 上线用，需要第三方可复核的完整证据链。

> 请使用 agent-acceptance 技能，技能来源仓库为 https://github.com/LPK3215/agent-acceptance，对项目做重度检查（完整验收）。先执行第 1 章定档问卷，再按第 2 至第 9 章逐层核对检查点，最后进第 10 章收口合成完整验收结论单。关键结论逐条附证据，无证据的判定标记为未证实。可分批多轮执行，每章一次会话。

会拿到：完整验收报告底稿，含定档记录、各章判定表、验收结论单、未证实项清单与改进闭环，可供第三方复核复现。判据细节可读 [10 验收结论与档位](references/10-验收结论与档位.md) 与 [附录A 元规则](references/附录A-元规则.md)。

### 自动（AI 全扫后自选）

适用场景：不确定该查多深，让 AI 先看看项目再决定跑哪个级别。

> 请使用 agent-acceptance 技能，技能来源仓库为 https://github.com/LPK3215/agent-acceptance，对项目做自动检查。先全扫项目源码与文档，给出检查级别建议与理由（可按面交叉，如本体跑轻度、安全跑中度），我确认后开跑。

会拿到：AI 选级别理由说明 + 按选定级别执行的完整产出。也可先从 [00 全局地图](references/00-全局地图.md) 通读正文，判据可与 GB/T 25000.51、OWASP Agentic AI Top 10、Agent Card 等外部框架对照。

**AI 选级别决策树**（检查者按此顺序判断，逐层决策）：

1. **项目子类识别**：扫描项目 README / package.json / 目录结构 -> 判定子类（应用型 / 框架脚手架型 / SDK wrapper 型）。
   - SDK wrapper 型 -> 建议**轻度**（大概率四问不过走快速出口，但由用户决定是否继续）。
   - 框架/脚手架型 -> 进入第 2 步。
   - 应用型 -> 进入第 3 步。
2. **脚手架型项目深度判断**：
   - 有 eval 套件 / CI 门禁 / 安全回归 -> 建议**中度**（本体 + 安全底线）。
   - 无 eval 套件但有完整文档和示例 -> 建议**轻度**（查骨架接线是否完整）。
   - 用户明确要求深度检查 -> 建议**重度**（按脚手架型子类口径判定）。
3. **应用型项目风险判断**：
   - 处理敏感数据 / 资金 / 生产环境 -> 建议**重度**（必须安全 + 评测 + 交付证据全查）。
   - 面向用户但不涉敏感 -> 建议**中度**（本体 + 安全底线足够初判）。
   - 原型 / Demo 阶段 -> 建议**轻度**（快速看骨架）。
4. **交叉建议**：AI 可建议按面交叉——如"本体跑轻度、安全跑中度"，并在理由中说明每面的建议级别和依据信号。
5. **用户确认**：AI 给出建议级别 + 理由后，由用户确认或调整，确认后按选定级别开跑。

> 技能是"体检单"不是"考试"。缺材料的章不会拖垮结论，只记"未评估"并在报告中写明缺什么、补哪些可以升档。1.1 四问不过则建议快速出口判 Demo；脚手架型 / SDK wrapper 型转为可选出口，由用户决定是否继续。

## 评估流程与产出

- 起点：回答第 1 章定档问卷，说明项目形态、技术栈、目标边界、成功标准与自主度，用于确定档位期望
- 过程：逐章检查。章首声明该层需提供的最低材料；材料不足时该层记为未评估，不视为通过，结论相应封顶并注明缺口与补齐优先级
- 耗时：四个检查级别对应不同时长，轻度一次会话完成，重度可分多轮执行，自动级别取决于 AI 判断结果
- 产出：验收报告底稿，包含档位结论、各章判定表、未证实项清单、安全红线与例外记录、改进闭环，可供第三方复核复现

## 使用边界

1. `block` 表示当前禁止放行，触发安全红线或证据不足以证明可信时给出，整改后复评可升档
2. 未评估不等于通过，任何未执行的面都会使结论封顶，缺口在报告中明示
3. 证据有等级，可复跑且可检查的证据优先于文档声称；对外场景中带章检测报告权重最高；无证据的结论一律记为未证实，不计入通过
4. 场景决定证据口径，内部自查不必配齐第三方口径；对外交付、合同引用与强合规场景须补齐证据等级，必要时由具备 CMA/CNAS 资质的机构出具报告
5. AI 负责执行评估流程，重大结论建议由人或第三方抽查证据链后再确认
