# agent-acceptance：AI Agent 项目工程验收与定档

一套 **Agent Skills 技能包**（文件夹即技能包），用于对任何 AI Agent / 多 Agent 项目做工程验收并给出档位结论。

**不评模型强不强，只查三件事：这个 Agent 项目拿不拿得出手、放不放得出去、该给什么档**（Demo / 原型 / 有限 Beta / 生产候选 / block）。低档不等于低风险——监管影响分级是独立轴。

## 这是什么

Agent 项目开发周期结束时的"工程验收 + 定档体检单"。判据按对象拆成 01-10 章（定档 -> 本体 -> 评测三层 -> 可观测 -> 安全底线 -> 生产就绪 -> 交付证据 -> 结论档位），每章是可直接执行的检查点表（查什么 / 达标信号 / 不达标信号）。判据全部自含，可第三方复核，不依赖本仓库之外的任何文件。

## 三种人怎么用

**1. 想把项目交给 AI 验收的人（最常见）**：把项目的仓库/文档/说明丢给你的 AI 助手，让它加载本技能执行即可。示例开场白：

> "用 agent-acceptance 技能，给我的 Agent 项目做一次验收体检。"

助手会自动从 `SKILL.md` 的章级路由表开始，先陪你过 01 定档问卷（只需口答：形态/技术栈/目标边界/成功标准/自主度），再按你能提供的材料决定逐层开查，最后给出档位结论。你不需要先读任何文档。

**2. 想自己当检查者逐章跑的人**：从 [`SKILL.md`](SKILL.md) 读起——它是唯一入口（定位 + 章级路由索引），按它指示直达 [`references/`](references/) 各章正文执行。

**3. 维护/扩包的人**：阅读 [`docs/00-写作与引用规范.md`](docs/00-写作与引用规范.md)，遵守写作纪律；机械项直接跑 `python docs/verify.py` 自查。

## 用起来是什么体验（先剧透，别懵）

- **会先被问什么**：01 定档问卷是最小门槛，口答即可；之后每层开查前，章头部会写明"被检方至少拿得出什么"。
- **缺材料会怎样**：记"该层未评估"，不是失败——结论自动封顶并写明缺哪层，顺便告诉你补建优先级。
- **要跑多久**：技能按"一次验收怎么走"给了三种跑法。想快速初判，一条主线（1 -> 2 -> 7 红线 -> 10）一次会话内出结果；要完整验收就按章分批，每章收口会给你一张判定表并指明接哪章，10 收口合成**验收结论单**。
- **最后得到什么**：一个档位结论 + 各层判定表 + 未证实项清单 + 改进闭环，可作第三方可复现的验收报告底稿。

## 目录结构

| 路径 | 内容 | 谁读 |
|---|---|---|
| [`SKILL.md`](SKILL.md) | 技能入口：定位 + 触发场景 + 三种跑法 + 章级路由索引 | 执行时先读它 |
| [`references/00-global-map.md`](references/00-global-map.md) | 章树全貌/查漏/扩容地图 | 想扫全貌时按需读，不是执行必经 |
| [`references/01`-`10`](references/)（章正文） | 判据正文：定档 / 本体 / 考卷 / 判分 / 指标 / 可观测 / 安全 / 就绪 / 交付 / 档位 | 执行时按路由逐章加载 |
| [`references/附录A-元规则.md`](references/附录A-元规则.md) | 检查者纪律：不评什么 + 反模式自查 | 判结论 / 审报告时 |
| [`skill.json`](skill.json) | 机器可读元数据（name/version/author），与 `SKILL.md` frontmatter 同源 | 技能生态与发布工具 |
| `docs/` | 作者/维护文档：写作纪律 + 打包自查 + [`docs/verify.py`](docs/verify.py) 自查脚本 | 技能作者与维护者 |
| `scripts/` | 作者运维脚本：一键检验 / 一键发布（见下"维护者速查"） | 技能作者与维护者 |
| `.codebuddy/` | 本地 IDE/记忆数据 | 不入技能包 |

## 维护者速查（一键命令）

| 你要做 | 命令 | 说明 |
|---|---|---|
| 一键检验 | `python docs/verify.py` | 机械项自查：FAIL 为 0 即放行；WARN 仅外部官方链接，按 R3 人工确认 |
| 一键发布（打包 zip） | `python scripts/release.py package` | 先校验，通过后打 `dist/agent-acceptance-<版本>.zip`（zip 顶层即技能目录，解压即用） |
| 一键发布（装到本机 CodeBuddy） | `python scripts/release.py install` | 先校验，通过后同步到 `~/.codebuddy/skills/agent-acceptance/` |
| 一条龙（校验+打包+装机） | `python scripts/release.py` 或 `python scripts/release.py all` | 推荐给日常改完发布用 |
| 双击版入口 | `scripts/verify.cmd` / `scripts/release.cmd` | Windows 双击即跑，跑完停留显示结果 |

发布物边界：`SKILL.md` + `skill.json` + `references/`；`docs/`、`scripts/`、`.codebuddy/` 不参与技能运行、不进发布物。

## 维护须知

- 改判据只改 `references/` 对应章正文，**不动章号与判点号**（判点号是稳定主键，正文互引用它）。
- 新增检查面：先到 `00-global-map.md` 过"扩容三关"（通用 / 公用 / 可判）再落正文。
- 技能运行时不得依赖 `docs/` 任何文件；`docs/` 不反向链入运行时正文。
- 每次改动后跑一键检验：FAIL 为 0 即机械项放行；WARN 只出现在外部官方一手来源链接，按写作规范 R3 人工确认。
- 发布走一键命令：机械项先过 `docs/verify.py`，语义项（四节清单里机器不可判的）发布前仍须人工过一遍 `docs/00-写作与引用规范.md`。
