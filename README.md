# agent-acceptance：AI Agent 项目的工程验收与定档

给任何 AI Agent / 多 Agent 项目做**工程验收 + 定档**的公开标准（Agent Skills 技能包，文件夹即技能包）。它回答三个问题：这个项目**拿不拿得出手、放不放得出去、该给什么档**。

结论档位：`block` / `仅 Demo` / `原型` / `有限 Beta` / `生产候选`。低档不等于低风险——是否触碰资金、隐私、人身等监管敏感面，是另一条独立判断轴。

**不评什么**：不评"模型能力谁强谁弱"，不代替第三方资质检测与带章报告。它评的是**工程与证据**：判据全部自含，任何第三方都能照着本仓库复核出同一结论。

## 我属于哪类人，就从哪段看起

### 1. 甲方 / 业务验收方：要确认"交付的东西值不值得接收"

- **你想要的**：可信结论 + 可复核依据，而不是技术过程。
- **怎么做**：把项目的仓库、文档、演示材料连同本技能交给 AI 助手跑一次完整验收，让结论落在"证据等级（9）"与"档位结论（10）"上；关键判定要求出示对应证据逐条核对。
- **你会得到**：档位结论、各章判定表、**未证实项清单**（哪些结论没证据、不能算数）、一份可作第三方复现报告的底稿。
- **从这里开始**：先读 [结论档位怎么给](references/10-验收结论与档位.md)，再读 [检查者纪律](references/附录A-元规则.md) 弄清底线与反模式。

### 2. 交付团队 / 开发者：要知道"上线前还差什么、怎么证明做好了"

- **这库对你不是被审清单，是标准答案库**：10 章把该管的面拆成检查点表（查什么 / 达标信号 / 不达标信号），每条都告诉你"证据长什么样"。
- **推荐路线**：先过 [1 定档](references/01-范围、形态与档位.md) 明确目标与档位期望（问卷口答，几十分钟），再按 [2 系统组成](references/02-系统组成与真实接线.md)、[3 考卷与评测集](references/03-考卷与评测集.md)、[4 判分规则](references/04-判分规则.md)、[5 指标与目标值](references/05-指标与目标值.md)、[6 运行可观测](references/06-运行可观测.md) 逐层自检；[7 安全与权限底线](references/07-安全与权限底线.md) 必须全绿；[8 生产就绪与上线](references/08-生产就绪与上线.md) 与 [9 交付物与证据链](references/09-交付物与证据链.md) 补流程与证据；最后 [10 对分定论](references/10-验收结论与档位.md)。
- **你会得到**：一张能逐条打勾的自检表，和"哪层没查 = 结论自动封顶在哪"的整改优先级。
- **从这里开始**：[1 章定档问卷](references/01-范围、形态与档位.md) 是最小门槛，口答即可，不需要先读任何文档。

### 3. 想把验收外包：让 AI 助手替你跑（最省事）

- **怎么做**：对你的 AI 助手说一句开场白（见下方"快速开始"），它会从 `SKILL.md` 的章级路由开始自动执行。
- **三种跑法**（[SKILL.md](SKILL.md) 有完整说明）：
  - **快速初判**：一条主线（定档、本体接线抽查、7 安全红线、10 结论）单次会话出结果；
  - **分批全量**：按章逐步开查，每章收口交一张判定表并指明接哪章，10 章收口合成验收结论单；
  - **红线急查**：只跑 7 安全底线与 10 结论，适合"先告诉我能不能放出去"。
- **注意**：AI 是执行引擎，不等于自动通过——关键结论请人工复核证据（原因见"边界与诚实声明"）。

### 4. 学习者 / 第三方复核人：想弄懂"Agent 项目该管哪些面"

- **把 [00 全局地图](references/00-global-map.md) 当地图、10 章当教材**：从需求边界、本体组成、评测三层、运行证据、安全底线、生产就绪到交付证据，一页读懂验收全景，适合写评审规范、授课或给采购做技术尽调。
- 判据可与外部框架对照着读：GB/T 25000.51 八特性、OWASP Agentic AI Top 10、Agent Card 十项证据门槛等，正文都给了出处与引用纪律。
- **从这里开始**：先读 [全局地图](references/00-global-map.md)，再按 P0 到 P3 顺序逐章读。

## 快速开始（对 AI 助手说一句）

> 用 agent-acceptance 技能，给我的 Agent 项目做一次验收体检。

先看结论、再补过程：

> 用 agent-acceptance 技能，对我的项目做安全红线急查，只回答能不能放出去。

## 一次验收是什么体验（先剧透，别懵）

- **会先被问什么**：1 章定档问卷（形态 / 技术栈 / 目标边界 / 成功标准 / 自主度），口答即可；之后每层开查前，章头部会写明"被检方至少拿得出什么"。
- **缺材料会怎样**：记"该层未评估"，不算失败——结论自动封顶并写明缺哪层、补建优先级是什么。
- **会花多久**：三种跑法对应不同时长；快检一次会话出结果，全量可分多轮跑。
- **最后拿到什么**：档位结论 + 各层判定表 + 未证实项清单 + 红线与例外记录 + 改进闭环——一份第三方可复现的验收报告底稿。

## 为什么可以信这份标准

- **判据自含**：每章判据不依赖本仓库之外的任何文件；外部实证标注出处、版本与引用纪律（已回源 / 待回源 / 单源口径之分），复核时按名检索即可。
- **机器校验 + 语义规范双护栏**：[docs/verify.py](docs/verify.py) 自动检查结构、链接、字符纪律、文件名与章标题主题词三方一致、判点引用完整性、地图与正文小节双向对齐；语义规则见 [写作与引用规范](docs/00-写作与引用规范.md)。
- **回归状态**：历次打包前机械项 `FAIL 0`，`WARN` 仅来自官方一手来源链接（按引用纪律 R3 保留）。

## 边界与诚实声明（用之前先读这五条）

1. **block 不是否定**：`block` 的含义是"现在放出去会出事"（安全红线触发或无法证明可信），整改后可复评、可升档。
2. **未查等于未评估，不等于通过**：哪层没跑，结论就封顶在哪，报告明说缺口。
3. **证据分等级**：可复跑可检查的证据高于文档声称；第三方带章报告在对外场景最高；没有证据的结论一律按"未证实"降级，不混入通过（见 9 章证据等级）。
4. **自用可降档**：内部自查不必配齐第三方口径；对外交付、合同引用、强合规场景，需按 9 章补证据等级，必要时由 CMA/CNAS 机构背书。
5. **AI 代跑要复看**：本技能让 AI 助手当执行引擎，但重大结论建议由人（或第三方）抽查证据链后再签字。

## 给维护者与贡献者（很短）

- 规则与纪律：[docs/00-写作与引用规范.md](docs/00-写作与引用规范.md)。改判据**不动章号与判点号**（判点号是稳定主键）；新增检查面先到地图过"扩容三关"（通用 / 公用 / 可判）。
- 机械自检：`python docs/verify.py`，`FAIL 0` 即放行。
- 一键发布：`python scripts/release.py all`（校验、打包、装机）。
- 发布物边界 = `SKILL.md` + `skill.json` + `references/`；本文件与 `docs/`、`scripts/` 不参与技能运行、不进发布物。
