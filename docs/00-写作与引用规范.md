# 00 写作与引用规范（agent-acceptance 作者维护文档）

> **适用范围**：本文件管辖 **`agent-acceptance/` 技能包**内的全部正文文档——`SKILL.md` 入口、`references/` 下 `00-全局地图.md`、章正文 01 到 10、附录 A 与附录 B，写作与返工时一律遵守。
> **打包边界**：技能包整体 = `agent-acceptance/`（入口 `SKILL.md` + `skill.json` 机器可读元数据 + `LICENSE` + `references/` 正文），三层互链全部用**技能包内相对 markdown 链接**，不依赖包外任何文件。本文件位于 **`agent-acceptance/docs/`（项目目录内作者维护文档区）**，仅作者/维护者在库内编辑期使用；发布技能生态时只取 `SKILL.md`、`skill.json`、`LICENSE` 与 `references/`，本区随项目仓库保留、不参与运行。
> **链接纪律**：技能包内一律用相对路径 markdown 链接（根目录指向 `references/xxx.md`，`references/` 内同目录互链）；不使用 Obsidian wikilink 语法——打包后外部读取方不识别 `[[...]]`，会变死链。
> **结构依据**：技能包形态对齐 Agent Skills 官方规范（agentskills.io/specification）——frontmatter 必填 `name`（仅小写字母/数字/连字符，与所在目录同名）+ `description`（不超过 1024 字符，第三人称写明"做什么 + 何时用"）；版本号、作者等自定义字段一律放 `metadata:`；`SKILL.md` 正文保持 500 行内、只做入口不做判据正文；参考文档全部收进 `references/`，`SKILL.md` 到正文引用保持一层深。改结构前先对照该规范，不随意发明新形态。

## 一、四条铁律（违反即返工）

### R1 链接白名单
- 技能包文档里出现的链接，目标**只允许**技能包内部文件（入口 `SKILL.md`、`references/` 下 `00-全局地图.md` 与各章正文、附录 A 与附录 B）。
- 指向区外的链接（素材 / 绝对参考 / 文献 / 产出区其它子目录 / 库内任何别处）与指向 `docs/` 维护区的链接**一律禁止**——区外文件打包时不随行，维护区不属运行时正文，链了都是死链或多余依赖。
- **不链接文字即通行证**：纯文本写文件名、章节号不需要链接，也就没有死链风险。

### R2 信息自含
- 每一章正文必须**自带该面验收所需的全部真实信息**：判据、数值、阈值、判法、达标/不达标信号直接写进文档。
- 素材 / 绝对参考 / 本地摘录档只在**写作期**当依据用；成文之后，这份文档不依赖任何区外本地档存活（删掉素材区、文档照样能独立执行）。
- **禁止"索引层"写法**：不许写"想看细节点这个本地档"式外置——别人拿不到那个本地档。
- 内部交叉引用默认用纯文本章节号（如"与 4.6.5 分工""地图 5.2 口径联动"），不产生任何链接依赖。

### R3 延伸参考仅限网络资源
- 正文实在放不下、确需延伸时，**只写可联网检索的一手来源**，纯文字：论文名 / 框架名 / 公开课程 / 标准号 / URL / 检索关键词（例：`TraceElephant（公开研究）`、`OTel GenAI semconv`、`suyoumo.github.io`）。
- **禁止写本地文件依赖**：本地档不可打包、他人搜索不到，写了等于没有。
- 拿不准是否公开可查的来源，宁可删掉也不写。

### R4 符号纪律（只用普通可识别字符）
- 判定信号一律用文字：**达标 / 警示 / 不达标**，不画勾叉、警示三角、叉号等图形符号。
- **字符黑名单（全文扫描为零，一律以文字或 ASCII 表达）**：图形符号与 emoji（勾叉、警示三角等）、章节段号、各类箭头、间隔点、省略号（改用"等"字）、全角竖线、非 ASCII 数学排版符（不等号、约等号、乘号、除号、求和号、上标、逻辑符号等）。
- **换算对照**：不等于写"不等于"；约等写"约等于/约"；相乘写"乘以"或 ASCII `x`；除以写"除以"或 `/`；平方写 `^2`；等价用文字描述（如"两式等价"）；范围连字符用 ASCII `-`（en dash 与单发 em dash 均不用，中文破折号仅成对使用于行文停顿与表内空位）；流程/演进用文字词（到/则/进而），不用箭头。
- **仍可用的正常字符**：中文标点（，。；：""''！？、（）《》）、中文破折号 `——`（行文停顿与表内空位）、比较符 `≥ ≤ ±`、百分号 `%`、数字与字母、ASCII 常用符号（`/ - _ + = < > ( ) [ ] . @ # $ ^`）及 markdown 语法字符。
- **动机**：正文会被 AI 反复读取与复述，图形/变体/生僻符号在部分模型与渲染环境易走样；统一普通字符可保证任何工具读到的语义一致。

## 二、链接与引用的处置规则

| 原写法（禁止） | 处置 |
|---|---|
| `[[绝对参考/某摘录\|某摘录]]`、`[[素材/某档]]`、`[[00-写作与引用规范]]` 等 wikilink 或指向维护目录的链接 | 删除链接；若其携带正文没有的关键信息，把**信息誊入正文**，不留链接；指向维护目录的写作纪律类说明直接省略（技能运行不需要） |
| 头部"本章弹药"整块（一批区外档名的 wikilink 列表） | 改写为 `溯源参考（联网可检索，非本地依赖）` 文字段：把实证值/判据已入正文的部分删链留文，再补该章真正用到的**公开一手来源名**（论文/框架/课程/URL） |
| 表内/句内"（某内部摘录档名 + 编号）"括注 | 删括注；括注里的实质数值或口径若正文未含，提到 达标/不达标 列或表后"口径注" |
| 本地自产档名（如"素材收敛第 2 层"）作判据出处 | 不再出现；出处只写可联网检索的公开名或删 |
| 区内引用 | 纯文本 `x.y` / `判点号`（如 `6.2.2`），不链文件名——文件名允许漂移，判点号是稳定主键 |

## 三、章节正文统一结构（表格化判据的规范式样）

### 命名纪律（文件名 / 首行标题 / 地图小节 三方对应）

`references/` 下每个章正文文件存在**一个共享主题词**，由三处共同持有，必须逐字一致（`scripts/verify.py` 的 `check_title_topic` 自动校验，改一处不跟上另两处即 FAIL）：

1. **文件名** = `NN-主题词.md`（如 `01-范围、形态与档位.md`；NN 两位补零，用于文件排序）。
2. **章首行标题** = `# NN 主题词`（如 `# 1 范围、形态与档位`）——标题**不带任何括注**；功能括注（"拿什么验 / 怎么算对 / 多少算好…"）只允许出现在 `00-全局地图.md` 的小节标题与章内 `查什么` 行，不写进章 H1。
3. **地图小节标题** = `## NN. 主题词（可带功能括注）`（如 `## 3. 考卷与评测集（拿什么验）`）——主题词部分必须与文件名、章 H1 一致。

特例：`00-全局地图.md`（地图本身）与 `附录A-元规则.md`（附录，前缀 `附录A-`）不套用 `NN-` 编号，但同样遵循"主题词共享"——改文件名时必须同步改其余两处。

每章按下列骨架写，顺序不换：

1. **头部角色块**（> 引用行）：`本章角色`（地图 x 的展开正文 + 层级定位）到 `一句话`（本面查什么）到 `本章边界`（防越界，指明哪些内容归别章，不重复判）到 `依据原则`（自含声明，R2 落点）。角色块首行的"地图 x"回链 = `references/` 同目录 markdown 链接指向 `00-全局地图.md`。
   - 可选附加行（仅 01-03 入口/主干章在用，非强制模板）：`被检方提供物`（该层开查门槛）与 `使用方式`（逐条过法）。已设的章保留；新增章如无必要不加。
2. **溯源参考段**（可选，见上表规则 2）：只列该章真正用到的公开一手来源。
3. **正文小节导航**（仅 >100 行长正文必加）：`> **正文小节导航**：` 引用行列出该章全部 `##` 小节"编号 + 主题"（括号副注可省），分号连接，单引用行超 90 字自动折为连续引用行，插在分隔线后、首个 `##` 前——保证模型部分读取长文件时仍能看到整章范围。
4. **各节正文**：`## x.y` 到 `查什么`（1-2 行，把"为什么查这节"的来由讲清）到 **判据表** 到 `检测注意事项`（操作细节、判错场景、与别章边界）。

### 判据表式样（R2 的核心载体）

- **表头固定四列**：`检查点 | 查什么 | 达标信号 | 不达标信号`。
  - 曾存在的"依据"列**已废除**——出处信息按 R3 走正文文字或溯源段，不再逐行占列。
  - 例外：**档位对照矩阵**（如 01 章 1.6 的 G1-G4 逐层加码表、各层分档映射表）允许用"G1|G2|G3|G4"式的多列表格，表头首列写清楚维度；逐条判点表仍须固定四列。
- 表内**只写真实判据**：阈值、判法、红线段，全部以本文件内容形式完整出现。
- 含"为什么这么判"的关键实证口径（如某阈值源自哪篇实证），下沉为表后 `检测注意事项` 或紧邻"口径注"，纯文字，不链本地。
- 参考值一律标注：**"参考口径"**（并注明须按项目场景自推导），不当铁律；实证数字注明公开出处名可按名检索。

### 写作红线
- 禁止空话/虚句（"应重视可观测性""提升用户体验"一类不落地表述）。
- 无源不落硬判据；多源阈值冲突时并列标参考口径，不冒充定论。
- 口吻：客观、可执行、第三人称给检查者用的操作规格；不堆背景叙事（背景/基本情况沉区外，不进正文）。
- 每章收口给出**输出物**与**后续分诊**（接哪几章、缺件如何降级），保证"读完即知怎么用这份判定"。

## 四、打包前自查清单

> 机器可判定项已固化为可运行脚本：仓库根目录执行 `python scripts/verify.py`，FAIL 为 0 即机械项放行。WARN 常态只有外部官方一手来源链接（按 R3 人工确认）；若另出现 `updated` 双写不一致的 WARN，属需修复项，同步后即消失。下列逐条仍须人工复核机器不可判的语义项，确认后再发布。
>
> 发布流水线（校验 -> 打 zip -> 装本机）已封装为一键工具：`python scripts/release.py`（具体用法见仓库 README"参与维护与贡献"）。本清单 = 发布前的人工复核关，机器脚本不能替代。

- [ ] 技能包内全文搜不到 `[[`（Obsidian wikilink 一律清零）；链接均为技能包内相对路径 markdown 链接（根目录到 `references/xxx`，`references/` 内同目录互链），指向包外的链接为零。
- [ ] 删除任何"详见某本地档/素材/绝对参考/维护文档"的表述；确需延伸处均为可联网检索的文字来源。
- [ ] 各判据表为四列式样，无"依据"列残留；参考值带"参考口径"标注。
- [ ] 每章头部有 `依据原则` 自含声明；弹药块形式已不存在（改为溯源参考文字段）。
- [ ] 章间引用全部为纯文本 `x.y`/判点号，不引用文件名。
- [ ] 正文超 100 行的文件顶部有 `正文小节导航` 引用行（编号+主题，覆盖全部 `##` 小节），低于 100 行可省。
- [ ] 黑名单字符扫描为零（图形符号与 emoji、章节段号、各类箭头、间隔点、省略号、全角竖线、非 ASCII 数学符、en dash）；仅剩允许列表（中文标点 / 中文破折号成对 / 比较符 ≥ ≤ ± / ASCII）。

- [ ] SKILL.md 执行硬协议锚定存在（入口必经 / 收口必经 / 产出必落盘 / 输出目录声明与默认目录 / 开跑复述钩子 / 01 与 10 必经章链接）——硬协议是运行期"触发即必达"的最硬保证，删除或挪出 SKILL.md 常驻层会被 verify 以 FAIL 拦下。
