# 01 项目结构与流程图（作者维护文档）

> 本文件用图的方式回答三个问题：**这个包由什么组成**；**章 1 如何分流决定查哪些章**；**一次完整验收从头到尾怎么走**。
> 适合场景：新成员上手、回顾全貌、向他人讲解项目时直接截图使用。

---

## 1. 技能包文件结构（三层渐进式披露）

```mermaid
graph TD
    L1["第 1 层：元数据（常驻，用于发现）<br/><br/>skill.json + SKILL.md frontmatter"]
    L2["第 2 层：入口（触发时加载，用于路由）<br/><br/>SKILL.md 正文：说明 + 章级路由索引表<br/>（每行直达一章正文）"]
    L3["第 3 层：判据正文（按需读取，用于执行）<br/><br/>references/ 目录：<br/>00-全局地图（全貌图，非必经）<br/>01-10 章正文 + 附录A"]

    L1 --> L2 --> L3

    style L1 fill:#e8f4fd,stroke:#2196F3
    style L2 fill:#fff3e0,stroke:#FF9800
    style L3 fill:#e8f5e9,stroke:#4CAF50
```

**核心规则**：
- 引用只有一层深：`SKILL.md` 直达 `references/` 各章，无第三层
- `00-全局地图.md` 与章正文平级，不是中间索引
- 打包单元 = `SKILL.md` + `skill.json` + `references/`；`docs/` 和 `scripts/` 不参与发布

## 2. 章 1 分流决策图（核心机制：不是每次都全跑）

```mermaid
flowchart TD
    START(["开始验收：任何跑法都从章 1 起"]) 
    CH1["章 1 定档问卷<br/>回答 5 个问题：<br/>要不要 Agent / 什么形态 /<br/>有什么材料 / 做到什么程度"]
    DECIDE{"根据定档结果分流"}

    CH1 --> DECIDE

    DECIDE -->|"不需要 Agent"| REJECT["拒绝立项<br/>建议替代方案（Workflow/RAG）"]

    DECIDE -->|"有源码+文档"| P1["P1：章 2 组成可查"]
    DECIDE -->|"无源码"| SKIP1["章 2 记'未评估'"]

    P1 --> DECIDE2{"有测试集/评测基建？"}
    DECIDE2 -->|"有"| P2["P2：章 3-5 评测资产"]
    DECIDE2 -->|"无"| SKIP2["章 3-5 记'未评估'"]

    P2 --> DECIDE3{"有可运行部署？"}
    DECIDE3 -->|"有"| P3["P3：章 6-9 运行与交付"]
    DECIDE3 -->|"无"| SKIP3["章 6-9 记'未评估'"]

    SKIP1 --> DECIDE3
    SKIP2 --> DECIDE3

    P3 --> FINAL["章 10 收口：合成定档<br/>缺的层自动封顶 + 写明补什么可升档"]
    SKIP3 --> FINAL

    style START fill:#fce4ec,stroke:#E91E63
    style REJECT fill:#ffebee,stroke:#F44336
    style FINAL fill:#fff8e1,stroke:#FFC107
    style SKIP1 fill:#f5f5f5,stroke:#9E9E9E,stroke-dasharray: 5 5
    style SKIP2 fill:#f5f5f5,stroke:#9E9E9E,stroke-dasharray: 5 5
    style SKIP3 fill:#f5f5f5,stroke:#9E9E9E,stroke-dasharray: 5 5
```

**读图要点**：章 1 是必经入口，它的真正作用不只是“定档”，更是“分流”——决定后面哪些章上场、哪些跳过。缺材料的章不是失败，是“未评估”，结论会因此封顶但不会卡死。

## 3. 完整验收的章节流程（全跑场景）

```mermaid
flowchart TD
    START(["用户发起验收请求"])
    LOAD["AI 加载 SKILL.md<br/>读取路由索引"]

    subgraph P0["P0 定档问卷（章 1）"]
        Q1["1.1 是否真需要 Agent<br/>（过度设计四问）"]
        Q2["1.2-1.5 形态/技术栈/<br/>边界/成功标准"]
        Q3["1.6 自主度档位 G1-G4"]
        OUT1["输出：定档记录"]
    end

    subgraph P1["P1 组成可查（章 2）"]
        S2["逐块检查 13 大模块<br/>模型/上下文/循环/规划/<br/>工具/记忆/RAG/数据/编排..."]
        OUT2["输出：缺件表 + 接线判定"]
    end

    subgraph P2["P2 评测资产（章 3-5）"]
        S3["3 考卷可信度"]
        S4["4 判分规则"]
        S5["5 指标与目标值"]
        OUT35["输出：评测层判定表"]
    end

    subgraph P3["P3 运行与交付（章 6-9）"]
        S6["6 可观测"]
        S7["7 安全底线（必查）"]
        S8["8 上线就绪"]
        S9["9 交付物与证据"]
        OUT69["输出：运行/交付判定表"]
    end

    subgraph CONCLUDE["收口（章 10）"]
        VETO{"否决项检查<br/>红线是否触顶？"}
        WEIGHT["加权定档<br/>（安全不占权重，一票否决）"]
        UNVER["收集未证实项<br/>（缺证据不混入通过）"]
        REPORT["输出：验收报告<br/>档位 + 判定表 +<br/>未证实清单 + 改进闭环"]
    end

    START --> LOAD --> Q1
    Q1 -->|不需要 Agent| REJECT["拒绝立项<br/>建议替代方案"]
    Q1 -->|需要| Q2 --> Q3 --> OUT1

    OUT1 -->|"有源码"| S2
    OUT1 -->|"无源码"| SKIP2["章 2 记'未评估'"]
    S2 --> OUT2

    OUT2 -->|"有测试集"| S3
    OUT2 -->|"无测试集"| SKIP35["章 3-5 记'未评估'"]
    S3 --> S4 --> S5 --> OUT35

    OUT35 --> S6
    S6 --> S7
    S7 --> S8 --> S9 --> OUT69
    SKIP35 --> S6

    OUT69 --> VETO
    VETO -->|"触顶"| BLOCK["结论：block"]
    VETO -->|"未触顶"| WEIGHT --> UNVER --> REPORT

    style P0 fill:#fce4ec,stroke:#E91E63
    style P1 fill:#e3f2fd,stroke:#2196F3
    style P2 fill:#f3e5f5,stroke:#9C27B0
    style P3 fill:#e8f5e9,stroke:#4CAF50
    style CONCLUDE fill:#fff8e1,stroke:#FFC107
```

## 5. 开发与发布流水线（维护者视角）

```mermaid
flowchart LR
    EDIT["编辑判据<br/>references/*.md"]
    SPEC["写作规范<br/>docs/00"]
    VERIFY["机械校验<br/>scripts/verify.py"]
    PKG["打包 zip<br/>dist/agent-acceptance-x.y.z.zip"]
    INSTALL["安装本机<br/>~/.codebuddy/skills/"]

    EDIT --> VERIFY
    SPEC -.->|管辖| EDIT
    VERIFY -->|FAIL=0| PKG
    PKG --> INSTALL

    FAIL{"有 FAIL？"}
    VERIFY --> FAIL
    FAIL -->|"是"| FIX["修复<br/>（链接/字符/结构/引用）"] --> VERIFY
    FAIL -->|"否"| PKG

    style EDIT fill:#e3f2fd
    style VERIFY fill:#fff3e0
    style PKG fill:#e8f5e9
    style INSTALL fill:#fce4ec
```

**命令速查**：
| 做什么 | 命令 |
|---|---|
| 仅校验 | `python scripts/verify.py` |
| 一键发布 | `python scripts/release.py all` |
| 仅打 zip | `python scripts/release.py package` |
| 仅装本机 | `python scripts/release.py install` |
| 双击执行 | `scripts\verify.cmd` / `scripts\release.cmd` |

## 6. 元数据双写同步关系

```mermaid
graph TD
    SKILL_MD["SKILL.md<br/>frontmatter:<br/>  name: agent-acceptance<br/>  description: ...<br/>  metadata:<br/>    author: LPK<br/>    version: 1.0.0"]
    SKILL_JSON["skill.json<br/>{ name, displayName,<br/>  description, version,<br/>  author, updated,<br/>  keywords }"]
    DIR_NAME["目录名<br/>agent-acceptance"]
    VERIFY_PY["scripts/verify.py<br/>检查 A 节<br/>逐项比对"]

    SKILL_MD -->|name == dirName| DIR_NAME
    SKILL_MD -->|description 同源同文| SKILL_JSON
    SKILL_MD -->|metadata.version == version| SKILL_JSON
    SKILL_MD -->|metadata.author == author| SKILL_JSON
    VERIFY_PY -.->|自动校验一致性| SKILL_MD
    VERIFY_PY -.-> SKILL_JSON
```
